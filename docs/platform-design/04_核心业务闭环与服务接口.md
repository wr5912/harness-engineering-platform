# 04｜核心业务闭环与服务接口

本章 W1–W7 是目标工作流设计；“平台管理助手当前能力”单独记录已实现接口及其边界，实际验收仍引用项目验收矩阵。阶段条件引用 [05](05_实施路线与迭代计划.md)，比较环境及 Trace 写权引用 [03](03_存储架构与数据契约.md)。方法、接口名和对象示例不表示当前实现。

## W1｜研究改进与比较

选一项有价值的实际输入或业务问题，固定 Baseline、Case、评审口径、Candidate、镜像、模型和工具来源。支持归因的失败、可能反驳它的成功观察与缺失 Case 一并保留，不用摘要补全原始证据。

```mermaid
flowchart LR
 I["实际问题 / 固定输入"] --> E["Experiment / 唯一 Candidate"]
 E --> ENV["核对外部状态 / 恢复或隔离"]
 ENV --> A["Baseline Run"]
 ENV --> B["Candidate Run"]
 A --> C["逐例比较 / 限制"]
 B --> C
 C --> D["人工 Decision"]
```

两个独立 HOME 和 Session 不能隔离共享业务后端。每个 Case 的执行前状态、数据快照、复位或 namespace、执行顺序及实际核验按 [比较环境合同](03_存储架构与数据契约.md#comparison-environment)记录。不能控制外部状态时，只作带限制的观察比较，不宣称 Harness 引起了差异。代码中的 `comparable` / `causal_comparable` 仅表示已记录条件的检查结果，不替代因果论证。

修改写入正确 Experiment 的 `candidate/`，评测生成新 Run，旧 Run 不覆盖。由人将依据写入原有 `decision.md`；`adopt/continue/reject/inconclusive` 都是合法结果，不自动发布。

### 后续研究工作台与价值验证

后续研究工作台仍服务当前研究者。选择一个已有 Agent 和一项有原始证据的问题，将以下操作接成一条路径：

1. 明确选择 Agent、Experiment 和 Run，显示精确来源、Git 提交及 dirty 状态、实际装载记录。
2. 按场景查看完整 Case：当前 `evaluation.md` 定义、该 Run 冻结的输入和预期、实际输出、原始证据及已有归因分别标明来源。证据缺失时显示缺失，不用摘要补全。
3. 同时查看支持归因的失败、可能反驳它的成功观察与未覆盖 Case；执行是否完成、评判是否通过分别显示。
4. 在明确的 Experiment `candidate/` 中修改与问题相关的资产，复用现有评测入口运行所选 Case，生成新的 Run 并比较来源、观察、回归和限制；不覆盖历史 Run，不静默改变比较口径。
5. 由人将 `adopt`、`continue`、`reject` 或 `inconclusive` 及依据写入原有 `decision.md`。管理智能体可以帮助解释证据和准备修改，不能把推断写成事实、替人改评判标准或把研究判断当成业务发布许可。

计划中的 Agent 中心工作台将连接这条维护路径；当前只读首页仅提供资产清单和来源。需要真实业务任务入口时，再扩展任务视图。确定性选择、查看、执行与记录不依赖自然语言入口。界面读取现有 `evaluation.md`、Experiment、Run 和 Decision，不建立第二套可编辑 Case 库或建议库。

用一项真实研究任务验证：选择未串错来源，候选改动进入正确工作树，新运行确实装载该内容，失败和缺失如实呈现，并比原操作减少实际步骤或来源错误。首条路径证明价值后，再按复用需求用第二个 Agent 或另一种 Variant 检验；若只是给现有 CLI 增加维护成本，就停止扩展工具。

## W2｜多算力变体（仅选定时）

只有资源或组件变化是当前研究假设时才建立独立 Candidate，事前说明任务质量下限、关键退化红线、资源预算及工具背后的模型调用边界。除冻结 Case 和评审器外，同样执行 `03` 的外部状态合同。CPU、内存、token、延迟和缺测分别记录；no-compute 未证实无远程模型调用时保持未知。

研究可以引用固定 Git Baseline；完整产品变体需要真实已发布、可恢复的父版本。两者不能互相代替，任务依赖见 [08](08_112项任务追溯矩阵.md)。

## W3｜实例装载与实际运行

明确 Agent、Experiment/固定来源、镜像、HOME 和读写卷，先检查来源解析，再在新实例或新 Session 核验实际装载和用户可见行为。研究实例启动不等于长期业务服务已经接管。实际健康、来源和工具目录来自运行观察并标时间，期望配置单独显示。

## W4｜失败或反馈到 Case，再到改进

从原 Run/Session/Trace 的精确引用提出问题和 Case 建议，先人工核实；原生 feedback 接口未实测支持时不预设版本更新、撤销或并发语义。确认后只编辑 Agent 原有唯一 `evaluation.md`，再建立 Experiment、执行新比较并写 Decision。提案不能自行修改标准答案或覆盖旧口径。

工具展示原问题、提案、已确认 Case、实际 Run、反例、回归与限制；有效 Baseline 存在时展示两端对照，无 Baseline 时保留缺口。比较仍遵循 `03`，证据链完整不自动构成因果证明。没有真实收益时保留手动路径。

## W5｜管理动作与可选 Meta-Harness

先用确定性选择、查看、执行与记录验证工具价值。只有自然语言管理有实际收益才引入 Meta；管理 HOME/Profile 与业务实例分开。Meta 解释证据并准备计划，修改经同一服务完成，不能直接覆盖任意文件或操作 Docker/SQL。

修改动作按需要形成目标与来源摘要、影响预览、有效确认、真实回执和状态查询。`accepted`、执行中、完成、失败、超时与 `unknown` 各有语义；远端副作用结果未知时先对账，不凭 request_key 保证恰好执行一次。

MG06 的 R4c 覆盖只能是目标澄清或已有资产操作，完整新建/导入依赖 AG06/AG07。MG08 的 R4c 覆盖只能是已可用能力的选择与验证，四类 Hub 的完整组合、发布和绑定依赖 R5 能力。未启用 MCP Composer 不阻断普通研究或管理切片，也不能声称 MG08 全部完成，详见 `08`。

## 平台管理助手当前能力

平台管理助手的业务 Harness 由数据工作区 `AGENTS.md`、`.agents/skills/` 中的管理研究技能、已启用扩展的业务技能维护，通过程序提供的系统提示装载、`platform_agents`、`platform_instances`、`platform_mcp`、`platform_task` 及原生 Session 任务上下文共同构成。数据原则规定管理身份与业务路由，具体流程和表达要求在对应 Skill 维护；程序负责可信定位、工具合同和执行边界。所有激活的管理会话使用四个领域工具与当前数据技能，按公开接口读取资产、研究资料和运行证据；专用任务再缩小动作范围。它与被管理业务 Agent 的 Harness 分开，不会因读取 Candidate 的 AGENTS.md 或业务轨迹而切换身份。

程序根由 `HARNESS_PROGRAM_ROOT` 定位，用户工作区由 `HARNESS_ASSET_ROOT` 和 `workspace.json` 定位；当前目录不决定资产归属。新管理 Session 记录工作区 ID，旧 Session 经明确的 legacyRoots 映射恢复，原始事件与 cwd 不改写。页面只更新最新上下文；按钮发起的目标 Agent、Experiment 或 Run 写入固定任务上下文，页面切换不改变本次目标。已确认创建新版本后，后续编辑对象使用服务返回的目标 ID。

管理工具的实例详情附带同工作区管理会话最新任务的只读交付记录，通过原生精确投影按工作区、会话归属、实例与来源核对，不重新运行交付探针。历史交付结果与实时实例状态分别呈现；未找到可核验记录不表示从未交付，已被同一会话后续任务替换的历史不在此最小查询范围。公共实例详情 RPC 与原始任务记录保持原合同。

管理助手通过工具枚举看到实际动作。普通管理写操作统一遵循 DSH 原生权限；“完全权限”允许的操作直接执行，平台不再叠加等待确认。`approval: never` 只表示拒绝需要询问的请求，不表示完全放行。普通资产写入、Decision 写入、评测启动和实例操作仍先执行真实 preview，校验目标、来源摘要与并发版本；校验失败不执行写入。特性整理和决策样本抽取继续在固定任务范围内自动保存并回读，人工标签复核与研究终端结论仍由人员办理。工具结果只返回实际状态与回执。历史待确认操作仅能在所属 Session 显式执行或取消，不因刷新或权限变化自动重放；确认、取消的回执立即更新卡片，再刷新核对。输入区仅展示待处理历史操作和执行中进度，已结束及结果未知的操作保留在原生消息历史；状态读取失败显示重试入口，不将旧状态写成当前成功。已确认融合的评测权限按真实 `source` 和约定 Case 判断，不能用额外 experiment_id 混淆目标。算力变体创建复用服务端 preview 并携带 expected_preview_sha256，执行前策略、所选 Case 或父版变化会拒绝；context/preview/compare 为只读，人工 confirm 不暴露给助手。固定来源通过 assets/read-fixed 读取 Candidate 内文件，核对 Agent、完整提交与来源摘要；排除凭据路径，二进制、超限或截断内容明确标记，不生成可编辑副本。

专用轨迹抽取在模型侧使用 `single-question-v1`：每次提交一个 question 与 target，由程序组装公共 v2 的 samples、questions、targets；公共 RPC、来源摘要、决策时点与标签校验不变，旧调用保持兼容。当前专用轨迹抽取仍只允许 `skill` 与限定 Run 的 `platform_agents` 取数/预览，不能调用实例、MCP、shell、子智能体或人员复核动作。通用维护流程不能解除该限制。特性整理专用会话同样只开放 agent-maintenance 和 platform_agents 的业务读取、特性预览；服务端固定 Experiment，预览通过后自动保存清单并回读。features/read-source 提供同一 Agent 的研究说明、观察和 Decision；历史 Experiment 相对引用按所属版本解析，新保存统一使用数据根相对引用。当前版本派生读取 detail.derivation 的可恢复父引用，未提交版本或 Candidate 与固定提交不一致时返回明确缺口，不能用 baseline_ref 或历史 parent_ref 替代。

算力变体专用会话只读取 `compute-variant-research`，工具限于 `platform_agents`、`platform_task` 和技能读取；原生作用域同时约束可见工具和实际执行。只读策划继续先以少量代表轨迹形成预览；生成执行通过固定目标的代码变体任务办理，不开放 shell、平台源码调试或其他管理技能。普通管理会话可选择四个领域工具；决策样本继续限定固定 Run。

`compute-variants/build-preview/build` 使用固定入口、当前 Candidate 摘要和真实构建预览摘要；`freeze-preview/freeze` 返回并核对完整 `freeze_input`，真实 Git 差异保留在操作记录中供展开核对，实际冻结前重新核对预览摘要并遵循 DSH 原生权限。`tasks/capabilities` 可限定 `server_id` 读取实际发现的工具 schema，组合绑定来自当前目录，缺失契约不靠名称推导。`context` 按实际文件、构建回执和 Run 返回生成、构建、冻结及装载状态；用户流程见 [06](06_界面与前后端渐进建设.md#36-不同算力需求的近似等效变体)，持久数据合同见 [03](03_存储架构与数据契约.md#当前代码变体与固定外部输入)。

研究方法通过 `platform_agents research/read-reference {topic}` 读取数据工作区的五个固定主题；`research/validate {experiment_id}` 复用程序侧 Experiment 校验，`legacy/inspect {path}` 只读清点 `evolution/history/imports/` 中的指定来源。研究说明 `hypothesis.md` 和 `evaluation/observations.md` 走现有文件编辑；`decision/preview` 与 `decision/update` 使用 `detail.decision.sha256`、`detail.change_sha256` 核对正文与结构化结论，校验失败恢复原文件。技术检查不代替效果评判。

当前接口支持文本读改、来源派生、即时评测及证据查询，尚不覆盖任意资产二进制编辑、删除/重命名、自动 Git 提交推送、Research Release 创建或长期自主调度。操作和回执保留在原生 Session；执行中断且没有完整回执时标记 unknown，先核对实际结果。评测执行关联可在重启后回读，受控任务须核对回执并显式恢复，不能承诺自动重试或续跑。固定来源不可恢复、外部模型或业务服务不可用时，报告具体阻塞及仍可完成的读取，不宣称业务通过。

<a id="task-delivery-interfaces"></a>
### 任务交付入口

管理对话通过 `task-builder` Skill 将用户目标与已有资产、工具和测试整理为一份方案。先查已有信息，仅对关键缺口集中询问；`platform_task preview` 校验范围，`start` 按 DSH 原生权限启动执行。已有目标必须来源可核对；改进已启用版本时从固定父版派生，使用真实回执绑定新 Candidate，不切换或覆盖原启用版本。创建角色和身份测试只表示资产已建立，业务测试与工具能力仍须单独验证。

能力查询与装配复用 `platform_agents` 的 `tasks/capabilities`、`tasks/assembly-preview`、`tasks/assembly-apply`。已知 Agent 或来源时限定查询范围；结果分别说明已发现资产、已配置工具及待运行验证的绑定。装配批量核对源文件、目标摘要与配置引用后写入，不执行被复制脚本。平台 MCP/API 连接使用上述数据根配置和共用保存入口；业务实例内部的原生连接仍按 Candidate/Profile 合同维护。评测沿用 `eval/preview/start/status/cancel`；需要业务报告时明确传入 `artifact_export`，从真实业务输出导出，不把评测报告充当业务产物。

`platform_task` 的 `begin-repair` 在修改前预留修复轮，`checkpoint` 查实际回执，`rollback` 恢复可核验的固定内容。页面通过 `assistant/task/status` 及任务卡的 `pause/resume/cancel` 查询和控制同一原生 Session，暂停信号直接送达活动操作。`deliver` 固定方案中的来源、Case、设备范围与业务工具要求，由后端执行检查及代表业务探针；活动任务不能通过领域交付入口绕开范围和预算。通过后交付卡提供实际智能体入口及 Run 业务产物下载；失败保留证据与具体缺口。预算、持久化、fork 和恢复的完整约束只在 [03 任务合同](03_存储架构与数据契约.md#task-delivery-contract)维护，源码与接口可达不代表真实构建或业务效果已经验收。

管理工具在模型侧逐步提供参数：先发现当前作用域的可用操作，再读取所选操作的输入合同，下一次请求只呈现该操作的参数结构。原公共 RPC、业务校验和授权范围不随模型投影改变；明确传入的冲突目标会拒绝，已有固定目标由服务器绑定。动态 MCP 参数来自真实发现的工具 Schema。业务流程与分支由数据 Skill 维护，程序不复制一套业务操作规程。

平台管理助手的 Bundle 默认模型为 `deepseek-official / deepseek-flash / max`；弱推理验收在独立 Profile 使用 `off`。用户 Profile 可覆盖，既有 Session 可能保留历史模型选择，验收以各次实际请求的 `request/header` 为准。仅对尚未执行工具的特定 DeepSeek 参数 JSON 解析失败重新生成同一步请求，最多两次；不自动补 JSON、不重放已完成操作，取消和预算继续生效。关闭推理的压力测试与真实小参数模型测试分别记录；研究方法见数据工作区[算力变体](https://github.com/wr5912/harness-engineering-platform-data/blob/main/docs/harness-research/compute-variants.md)。

确定性回归位于 `platform/plugin/test/assistant.test.mjs`、`agents-client.test.mjs`、`evaluation-client.test.mjs`、`extraction-scope.test.mjs` 和 `independent-workspace.test.mjs`，分别验证动作可达与确认、按钮固定目标、抽取限制及外置工作区读改回读。真实模型是否正确选 Skill、读取证据、提交有效提案及解释失败，需要部署环境中的管理对话验收；这些测试不能代替模型效果证明。

### 面向用户的反馈

表达要求唯一维护在数据 [`user-facing-output` Skill](https://github.com/wr5912/harness-engineering-platform-data/blob/main/.agents/skills/user-facing-output/SKILL.md)。平台通过 DSH 原生 Skill 注册表读取正文并装载到管理会话系统提示，覆盖进展、确认、完成和失败反馈。其他业务技能只定义对应流程，不复制表达规则；其他智能体可按自身 Harness 引用同一技能。普通原生会话不自动注入。是否保存、是否完成、待人工复核及影响判断的限制仍应清楚说明。

设计参考 [Canada.ca 内容指南](https://design.canada.ca/style-guide/)的任务导向与重要信息前置、[GOV.UK 完成反馈](https://design-system.service.gov.uk/patterns/confirmation-pages/)的结果和后续动作，以及 [Nielsen 的渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)；具体采用方式见上述原则。这些资料是设计依据，不是本平台用户效果的实验证明。[Poynter 介绍的华尔街日报专题写法](https://www.poynter.org/archive/2003/the-nut-graf-part-i/)常先用场景引入，再说明主题意义；这里借鉴解释意义的思路，不让操作反馈等待叙事铺垫后才交代结果。

其他业务智能体可以在自身 Harness 演进中引入该 Skill 的固定数据版本，并用领域任务验证；只有运行时实际装载才生效。独立部署需要携带正文时，从固定数据提交装配只读资产并保留来源引用，不另行维护表达规则副本。管理助手的加载不自动改变业务智能体的表达或证据标准。

## W6｜Hub、MCP 与组合工具

目录显示本次实际可用的 MCP、Skill、Plugin、知识源的来源、依赖和作用对象。目录发现、配置保存、实际装载、调用成功和评测通过分别验证；不自动执行未知插件，不预建商店和通用安装通道。

MCP 按锁定实现验证初始化、initialized 通知、工具/资源发现、受控调用及服务返回的 Session 标识；工具发现不是业务调用成功。单调用与组合的实施顺序见 [05](05_实施路线与迭代计划.md#mcp-composition-route)。

“工具与资源调试”同时支持服务器和已保存分组；分组详情的“调试分组”携带稳定分组 ID 进入同一页面，链接可刷新恢复。分组调试使用当前保存的发布地址和凭据，通过 MCP 客户端真实初始化、发现、调用工具与读取资源，不用本地聚合结果替代发布端点。资源模板按实际模板和参数展开后读取。未保存或失效目标不可执行；切换目标或保存配置新版本后清空旧目录和回执，丢弃在途旧响应，避免将其他目标的结果显示为当前结果。

知识保留原文版本与位置；运行事实来自确定性查询并带观察时间；研究材料引用原 Run。生成报告关联输入和证据，不自动升级为已核验知识。

<a id="mcp-business-composition"></a>
### 业务组合 MCP 工具

当多个细粒度接口共同完成一个业务步骤或子任务时，将它们组合成一个业务 MCP Tool。例如输入资产名称和时间范围，先查询资产，再用返回的资产 ID 查询告警，最后返回该资产的告警结果及证据引用。LLM 选择并调用这一个工具，执行器确定性地完成内部步骤，不在每一步再次调用模型。工具分组缩小候选工具范围，业务组合减少模型反复选工具和传参数；实际准确率与效率收益须由 [T12](07_关键POC验收与架构决策.md#mcp-composition-poc)比较验证。

原子步骤可以来自 OpenAPI 接口或已接入的 MCP 工具。复用现有 OpenAPI 调用、MCP 注册/客户端、凭据配置和登录凭据缓存，不另建连接或授权清单。开发者维护业务输入/输出、步骤依赖、参数映射和成功/失败判定，平台负责装载、验证、测试与发布；唯一源码和版本合同见 [03](03_存储架构与数据契约.md#mcp-composition-contract)。

首版提供只读流程图、输入表单、测试按钮和业务结果，允许展开实际步骤详情，界面交互见 [06](06_界面与前后端渐进建设.md#mcp-composition-ui)。首版不提供用户手动编排；这只是当前范围，未来有真实需求时再评估编辑功能，不预建拖拽编辑器或通用 DAG 引擎。图由定义生成，页面测试与实际 MCP `tools/call` 共用同一个执行入口。

组合返回有明确范围的业务结果和必要证据引用，避免将全部原始接口响应堆入模型上下文。前置步骤失败时停止依赖它的步骤，区分失败、未执行与结果未知；写操作超时且无法确认结果时先对账，不盲目重跑整个组合。执行器保留真实子调用和耗时，发布后的工具需由隔离 DSH 实际发现并调用。组合 Tool 发布不等于 Agent HarnessVersion 发布。

## W7｜业务版本发布、启用与回退（有长期业务需求时）

`HarnessVersion` 固定 Git 来源、资产摘要、标准 Runtime 镜像、Profile、能力与依赖版本、模型配置引用和非秘密运行配置；发布后不可变且可恢复。发布决定与 Research Decision 分开，由被授权操作者明确确认，记录身份、依据、摘要和时间。关键行为失败或证据不足时不发布。

`Deployment` 记录期望版本、回退目标与启用决定；`Instance` 显示容器和 DSH 的实际来源、状态及观察时间。统一入口的路由要用真实 Session 和业务结果核验，不能由容器健康推断。

采用所有新 Session 直接切换到已启用版本的规则，不设置灰度权重；已有 Session 继续绑定旧版本和实例。回退只改变后续新 Session 的路由，不能撤销既有输出、外部写入或承诺无损迁移在途 Session。旧实例保留到关联 Session 结束，且活跃 Schedule 停止或迁移已验证；无法恢复的会话明确失败。撤回版本不删除旧证据和引用。

## 多用户数据边界与选型门槛

当前平台面向个人开发者，未实现多用户授权或隔离。[EXP-007](https://github.com/wr5912/harness-engineering-platform-data/blob/9afc8fd0047367deb9df5b51595f101835359044/evolution/experiments/EXP-security-operations-expert-007/decision.md)的自动化试验只提供任务创建、查看、删除范围的证据；[门户 iframe 联调](https://github.com/wr5912/harness-engineering-platform-data/blob/12b6f552d4c15a475d9443c7029276810aafdbf4/agents/security-operations-expert/docs/门户联调记录.md)是单操作者试点，不证明 SSO 或 Session/Schedule 用户隔离。

既有 JSON 后端实例中，`DSH_HOME=/var/lib/dsh` 的任务目录为 `storages/schedule.json`，会话为 `sessions/`；这些是已记录的实例布局，使用前核对实际锁定版本和配置。Host 共享 Schedule 目录及原 Session 绑定，不等于平台用户归属。独立文件、Agent 容器和浏览器 owner 认证都不能证明同一 Host 内用户隔离。

已选择基于 DSH `v0.2.1-rc.2` 原生非 owner Peer／RemoteAccess 的共享 Runtime 路线。Session、Schedule 和执行历史使用同一个经服务端确认的用户身份与对象归属。逐一验证列表、读取、继续、取消、消息、附件、导出、任务 CRUD、历史、模型工具及后台定时投递的入口；不能只信调用方 Session ID、浏览器 Token 或前端过滤。归属隔离完成前，Host 级任务 catalog 不直接开放给多个用户。

开放前用两个用户在同一 Agent 下分别建立 Session 和任务，从 UI 与 Remote 交叉读、改、删和查看历史，检查模型工具、到期投递目标及重启后的归属。未覆盖入口保持关闭，不能为兼容降级为 owner；共享 Host 无法满足选定能力时记录原生接缝缺口并复议该能力，不擅自改变为另一隔离架构。此需求不引入完整 RBAC、租户或审批平台。

<a id="business-gateway-flow"></a>
## W8｜业务网关访问与撤权

1. 平台管理者在原管理入口维护 Agent 开放资格及用户访问规则；实例已启动仍可不开放，撤回开放不改写版本发布或研究决定。
2. 业务用户在独立业务来源登录，由辅助的用户认证与信任提供方核验个人凭据和稳定用户主体；这不代替智能体的凭据验证与可信来源核验。API 客户端使用受控凭据，浏览器采用插件建立的登录会话，前端不保存长驻上游 owner 凭据。
3. 业务网关先核对智能体的真实签名身份、所选实例的固定来源、身份启用与实例绑定，再检查开放资格与人到 Agent 使用授权；从同工作区的实例登记解析后端。业务入口以 Agent 和实例 ID 定位；只有 Agent ID 的入口提供经授权的实例选择，不隐式选取实例。新 Session 固定来源和实例，既有会话继续原绑定；实例重建时核对 Runtime 代次，不凭重用名称认领旧 Session。
4. 受信通道将主体和业务上下文交给实例适配插件，创建非 owner Peer。创建会话时持久保存归属，后续 UI、API、事件、附件和工具都消费相同归属。全局设置、凭据和宿主管理能力默认不授予业务用户。
5. 主体、Agent 开放或授权撤销时使当前授权失效，阻止新调用，并关闭或重新验证关联 WebSocket／流；仅注销路由不能清除已建立连接。恢复连接重新读取当前快照，不沿用过期许可。

身份依据与风险事实可缓存或按事件更新，不要求将身份内部检查及三类职责机械串成每次请求的多个远程调用。传输转发不改变业务权限；连接断开或模型取消也不证明远端业务副作用已回滚。插件合同见 [20](20_业务访问与运行控制插件开发规范.md)。

<a id="dynamic-mcp-control"></a>
## W9｜风险评估与 MCP 动态收紧

统一 MCP 管理在平台维护连接和目录；统一网关管理页配置智能体访问控制策略。开启风险评估后，输入、工具或资源操作、报告发布与下载事件自动触发对应智能体的实时风险评估，风险事实参与当前授权计算；手动重评仅是辅助入口。关闭评估时按静态工具策略和手动限制执行，开关及恢复合同见 [20](20_业务访问与运行控制插件开发规范.md#风险事实与访问控制策略)。它们通过可信上下文联动，不在业务访问网关重新配置 MCP，也不修改固定 Harness。

```mermaid
sequenceDiagram
 participant R as 风险评估
 participant A as 访问授权
 participant X as Runtime／组合执行器
 participant M as 统一MCP管理
 participant S as 上游服务
 R->>A: 风险事实（范围、原因、版本、有效期）
 A->>X: 新限制版本／失效通知
 X->>X: 更新有效快照，后续派发逐次检查
 X-->>M: 生效回执／覆盖／未确认状态
 X->>A: 子步骤／资源读取的当前许可
 alt 当前允许
 X->>S: 实际调用
 else 当前受限或必需事实未知
 X-->>M: 拒绝／暂停，无该次上游请求
 end
```

- **作用范围：** 明确用户、Session、实例、Agent 或服务，按真实范围收紧；会话 A 的风险不修改共享连接而误伤会话 B。工具、目标、参数和资源操作按实际粒度检查，不仅按工具名。
- **实时边界：** 同进程许可更新后，下一次派发使用新版本；跨实例以运行端回执或旧许可到期界定生效。首期选定的在线实例目标为规则提交后 2 秒内取得回执，跨进程许可快照最长有效 2 秒，运行端以本地单调计时在每次派发前检查租期，过期后暂停对应受保护动作。续租必须取得当前权威版本，不能靠通知到达自行延长。超时显示未确认；失联恢复先同步快照，再恢复受保护操作。这些数值是待 POC 验证目标，不是当前测量结果，不能宣称远端在保存瞬间已原子撤权。
- **执行覆盖：** 原生工具 Guard、MCP 转发、OpenAPI 直调、组合内部每个实际叶子、资源读取及排队或异步等待后的实际派发都检查；未纳管的后台执行器保持关闭，定时任务首期不支持。工具目录与原生权限快照的刷新辅助 UI／模型，不能替代执行前检查。
- **在途处理：** 运行端应用限制或许可到期后，已受理但尚未派发的受限请求立即阻止；组合在下一受限子步骤前停止。已发出请求尽力传递取消，并区分取消请求、已确认取消、完成和结果未知；不得把取消说成远端回滚。未知副作用先对账。
- **恢复与解除：** 主体撤销、风险失效、规则改变、重启或网络恢复后重新核对当前许可。风险解除触发重新计算，不自动恢复旧目录或旧授权；历史拒绝和回执不改写。

首个闭环为同 Agent 下用户 A、B 各有会话与任务：只收紧 A 的写操作，查询继续、B 不变；A 已开始的组合在下一写步骤前停止；页面可定位原因、版本和实际回执，重连与重启后约束保持。工具叶子执行、信任失效、必要确认和一种明确输出通道分别取证。输出前检查先选非流式报告，不能据此宣称聊天流、所有下载与推送均覆盖；若选择流式，必须验证被拒内容未先发送。新增风险规则或第二业务还需回归正常结果，不能只验证拒绝路径。
