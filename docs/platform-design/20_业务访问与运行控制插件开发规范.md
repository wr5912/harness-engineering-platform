# 20｜业务访问与运行控制插件开发规范

本规范定义统一网关的智能体身份、实时风险评估与访问控制合同。本轮实现范围为即时业务任务，实际装载与验证结果以项目验收矩阵及其证据为准。接入基线为 DSH `v0.2.1-rc.2`；平台和业务 Runtime 的实际升级结果以验收矩阵为准。系统边界见 [02](02_系统架构与部署设计.md#business-access-architecture)，事实写权见 [03](03_存储架构与数据契约.md#business-access-data)，业务过程见 [04](04_核心业务闭环与服务接口.md#business-gateway-flow)，实施顺序见 [05](05_实施路线与迭代计划.md#business-control-route)。本章唯一维护插件接口与一致性要求，不另建策略服务或资产副本。

## 1. 三类职责与执行责任

统一网关按“智能体身份、风险评估、访问控制”划分。凭据验证与可信来源检查同属智能体身份，不再把含义宽泛的“身份信任”作为一级功能。接入用户的登录与 Session 所属人另列辅助区，不能替代业务智能体身份。

| 分类 | 既有实现入口 | 职责与判断边界 |
|---|---|---|
| **智能体身份** | `AgentAuthenticationPlugin`、`AgentIdentityTrustPlugin` | 验证身份凭据、可信来源和实例绑定，管理身份启用与撤销。凭据验证回答身份声明是否成立；来源核验回答当前来源和代次是否符合登记要求。两项分别展示事实，共同构成身份前置条件。 |
| **风险评估** | `RiskAssessmentPlugin` | 根据当前输入、工具或资源调用、报告发布与下载等业务事件自动评估风险，输出有范围、时间、等级和依据的事实。身份过期、撤销和来源不匹配不折算为业务风险分数。 |
| **访问控制** | `AccessAuthorizationPlugin` | 维护服务、工具、资源和动作策略，结合身份条件、当前风险、资源归属与必要确认决定允许或拒绝；身份有效或低风险都不会自动增加基础权限。 |

智能体身份内的凭据验证通过后，仍须核对固定来源、实例代次和撤销状态。首期使用同一受信部署域内的 HMAC SHA-256 签名通道，来源摘要用于固定装载身份；这些依据不等于硬件远程证明、第三方认证或模型行为保证。没有实现的认证机制不能显示为可用选项。

身份条件未知、失效或不匹配时直接拒绝对应访问，低风险或人工确认不能放宽。风险评估按业务事件自动触发，手动重评仅用于故障恢复和核对。空闲周期巡检和定时任务到期前评估尚未覆盖，不能显示为低风险或已检测；影响见 [05 的首期定时任务边界](05_实施路线与迭代计划.md#首期定时任务边界与影响)。

三类职责不要求三个进程或三套存储。业务网关、DSH Remote、MCP/OpenAPI 与组合叶子在各自真实边界执行控制结果。前端隐藏、目录过滤或模型承诺不能替代服务端检查，确认及输出检查仍按实际阶段声明覆盖。

## 2. 公共合同、界面与唯一事实源

可导出的 TypeScript 合同唯一维护于 [`contracts.ts`](../../platform/plugin/src/business-control/contracts.ts)，管理端、网关和 Runtime 共同引用；执行实现在 [`core.ts`](../../platform/plugin/src/business-control/core.ts)。本文解释语义，不维护第二份字段定义。

### 智能体身份与用户归属

一个 Session 的所属人是接入用户，执行它的 Agent 是业务行为主体；两者不能混为一个 `userId`。接入用户认证与信任提供方只解决个人凭据、稳定用户身份和有效状态，在界面单列辅助区域，不替代智能体身份内的凭据验证与可信来源核验。凭据轮换不能改变既有资源归属；多人共享凭据只能形成同一接入用户。

Agent 身份与真实实例登记交叉核对，签名绑定实际接收实例、方法、路径、时间和一次性值。只有验签成功才产生认证证据，不能因配置文件存在或用户传入 `agentId` 就显示认证成功。删除登记后同名新建必须使用新代次，不能继承旧认证回执；同一持久实例的普通重启保留归属，但仍须重新完成签名握手。

可信来源摘要只保留一个配置位置。来源不匹配、人工撤销、有效证据缺失或过期均参与拒绝；不能用解除某项人工风险限制绕过这些条件。签名证明、策略应用回执与可信判断分别显示，保存策略不等于实例已经应用。

### 风险事实与访问控制策略

每条风险事实保留 Agent 和必要的用户、实例、Session、服务范围，以及级别、信号、来源、观察时间和有效期。按 Agent 汇总时仍保留这些范围：A 用户单会话的风险不能据此撤销 B 的权限，也不能将某次低风险评估写成整个 Agent 永久安全。没有新事实、未知或过期按真实状态呈现。

即时输入、实际受管工具或资源调用、报告发布或下载自动进入适用的评估阶段。评估结果先更新事实，再同步计算许可；异步等待和必要确认结束后，在实际网络派发前重验当前策略、身份条件、风险和目标。必需的评估不可用时拒绝相应受保护动作，不回退为未受限执行。

策略复用同一配置中的 Agent 服务与动作范围、操作允许清单，以及必要的人工限制。操作描述必须来自服务端实际解析的工具、目标、方法和参数；不能根据 GET 方法推断安全，不能把同名工具迁往新目标后沿用旧许可。组合固定版本和业务上下文，每个真实叶子独立检查，不为虚拟组合伪造外部目标。

### 统一网关界面与配置

业务入口按获准 Agent 展示三类事实：智能体身份内的认证方式、凭据状态与可信来源；实时风险与最近评估；访问控制策略与获准范围。用户登录另列；其他用户的会话、风险和资源不能混入本人页面。

平台管理界面通过一级导航“统一网关”（`#/gateway`）提供四个视图：默认“运行概览”，以及 `?tab=identity|risk|authorization` 对应的智能体身份、风险评估和访问控制配置。四视图共用顶部即时访问、身份、风险和回执摘要；运行概览集中展示实例应用回执、Agent 与接入用户身份事实、按 Agent 的风险状态、人工限制和最近 30 条执行结果。配置页不重复常驻运行面板。运行概览的“要限制的接入用户”从访问控制中已获准使用所选 Agent 的用户取值，支持多选并分别建立限制，不会授予使用权；指定 Session 或辅助重评时只能选择一位用户。限制解除必须选择该限制范围内的 Session 并重新评估；收紧与辅助重评显示各自结果。保存配置、实例应用与业务允许分别呈现。

智能体身份内分区配置 ID、HMAC 认证方式、可信来源与身份启用，接入用户认证和状态核验折叠在辅助区；风险评估配置提供方、必需动作及检测范围；访问控制维护服务、工具、资源和动作策略。“允许使用此 Agent 的接入用户 ID”填写认证提供方返回的稳定用户 ID，多个用逗号分隔；留空表示无人可使用。服务 ID 可从已登记 MCP 连接和操作清单建议中选择，也可手工输入；服务范围、动作和操作方法从当前受支持值选择。首次登记的操作 ID、实际目标，以及当前没有用户目录的接入用户 ID 仍需输入。未限定服务时按已登记操作开放，限定后未选任何服务时不允许访问。访问控制在宽屏并列展示 Agent 范围和操作清单，窄屏顺序排列；动作选项按需展开。模拟提供方明确标识为测试模拟，不显示为真实企业身份或完整业务检测。

当前业务配置唯一维护在数据工作区 `config/business-access.json`。界面和管理助手共用管理接口；三类配置跨页保留同一草稿，按页标记未保存内容，一次校验和原子保存整份配置。校验失败切到对应页并定位字段；外部变更保留草稿且阻止旧 revision 覆盖，可放弃草稿读取当前配置。状态轮询不覆盖编辑。凭据内容不进入状态投影，带凭据的地址不作为可见配置回传。提供方的“测试 HTTP 响应”仅以 `OPTIONS` 发送不含凭据和正文的请求，最多等待 3 秒且不跟随跳转；HTTP 405 只表示地址有响应，不代表 POST 合同、身份核验或风险业务结果通过。探测不保存配置、不创建测试 fixture。首期定时任务缺口、人工启动成本、延迟和漏执行风险在入口和管理页持续可见。

智能体从智能体管理共用的 `agents/list` 读取，支持按名称或 ID 搜索选择，关联 ID 只读显示；已有版本、业务实例及其实际来源供核对，不自动填入可信来源。当前找不到的已配置身份保留原值并提示，列表读取失败与空目录分别呈现。更换对象关闭该行业务开放、撤销身份启用并清除旧来源，其他策略草稿继续供复核；选择本身不触发认证、风险重评或业务执行。页内不重复展示一级菜单大标题，顶部摘要卡和运行概览中的详细回执均从同一状态读取。

### 智能体资产描述的当前映射

按用户提供的 GB/Z 185.4-2026《人工智能 智能体互联 第 4 部分：智能体描述》属性清单对照当前平台，身份页只读展示当前已启用 Experiment 的资产描述，不在业务访问配置中复制可编辑字段。`agents/description` 从该版本的 `candidate/harness.yaml`、Preset 和 Skill frontmatter 读取；“发现 Skill”仅证明资产中存在文件，不证明实例已装载、技能可执行或符合标准全部属性。

| 处理 | 描述属性／技能属性 | 当前事实与边界 |
|---|---|---|
| 直接展示 | `name`、`description`；`skills` 中的 `skillId`、`skillName`、`skillDescription` | 分别来自已启用版本的 `agent.name`、Preset `description`、`.agents/skills/*/SKILL.md` 路径与 frontmatter；缺值显示未登记。 |
| 仅作现有运行或来源信息，不映射为标准描述 | `version`、`authentication`、`accessAddress`、`accessMethod`、`capabilities` | Experiment ID 是来源定位，不是语义版本；HMAC 是平台接入策略；公开地址按实例登记；研究用能力声明不是已验证的对外能力目录。 |
| 当前缺少稳定事实 | `alias`、`iconAddress`、`provider`、`servingArea`、`defaultInputTypes`、`defaultOutputTypes`；技能的 `tags`、`examples`、`inputTypes`、`outputTypes`、`dependencies` | 当前资产没有可靠的同义字段和验证口径，界面不生成占位值。 |

本轮展示是有限资产投影，不声明 GB/Z 185.4-2026 的完整符合性；未来确有互联发布需求时，再确定各属性的所属事实源、版本语义与验证路径。

本次沿用原配置与接口，不迁移业务数据。`agentAuthentication` 保存凭据验证配置，`sourceDigest` 与 `agentTrust.enabled` 保存可信来源及身份启用条件，状态投影的 `trust` 保留技术字段名，但仅表示身份子检查，不是行为风险或综合信任评分。顶层 `authentication`、`identityTrust` 继续作为接入用户验证提供方，不能误用为智能体认证配置。合同与错误原因码保持兼容，原有拒绝条件不变。

## 3. DSH 装载与原生接入

- 使用 TypeScript 与 Cordis `Service`／`inject`，遵守注册、依赖就绪、卸载和 `dispose`。插件清单注明合同版本、兼容范围、实际覆盖和配置 Schema；缺依赖或配置不合法时明确失败，不隐式跳过控制。
- 网关使用隔离的业务监听和认证服务，不替换父平台的 Connection／owner 认证。注册 HTTP 与 WS 的同时登记清理器，卸载和撤权处理已有长连接；删除路由只阻止新握手。
- 实例接收经过认证的受信上下文并创建非 owner Peer。业务用户永远不转换为共享 owner。调用上下文用于承载身份，Session 归属存储用于持久所有权，两者缺一不可。
- 一个业务 Principal kind 只注册一个原生 `registerPolicy`；各插件向统一授权适配器提供事实。原生 `bindings()`、condition 与 `explain()` 为同步读取，不能直接返回 Promise 或在其中做网络风险分析。事实变化、撤销和到期时调用 `invalidate`，使原生快照及页面重读。
- 声明每个 Remote 方法涉及的全部资源。列表、搜索和流逐项检查；不能给业务主体宽泛 `global` 动作以替代对象归属。事件授权不自动裁剪载荷，因此只发送获准且不会夹带其他用户数据的事件。
- 原生权限快照只辅助界面；调用仍服务端检查。非 owner 页面注入对应快照，不能沿用默认 owner baseline。内存失效通知与跨实例分发是不同机制，跨实例仍需版本、回执与恢复快照。
- Exact Fetch 和插件自注册 HTTP 路径不自动经过原生 Remote 授权；逐路声明并检查，未支持路径保持拒绝。非 owner 原生交互参与仍有限制，必要确认必须验证专用接缝，不能临时提升 owner。
- 原生 `tools.restrict()` 约束继承的工具集合，当前作用域自己注册的工具仍可见；不能靠该掩码保证 MCP 撤权。工具注册、发现与重连都受相同能力上限约束，实际执行使用不可放宽其他拒绝结果的 `tools.guard()`，异步风险评估在它之前完成；排队或异步等待之后、实际网络派发之前再核对当前许可。
- 工具 Guard、文件、Shell、插件内部请求及代码变体不会因 RemoteAccess 自动获得读取隔离。每个已开放执行器取得真实 Session／任务上下文，并在执行前核对资源、目标与参数。受控工作目录和只读 Harness 不表示其他用户 HOME 不可读。
- 原生 `allows()` 在 owner 或 Remote 调用之外的允许结果不能作为模型工具的业务授权。内部执行器使用受信 `BusinessContext` 调用统一授权服务，不能因后台没有浏览器 Peer 而放行。首期业务 Profile 不启动定时服务、工具或页面；后续开放定时任务前必须补齐到期投递前的归属和授权重验，不能依赖创建时的一次许可。

## 4. MCP、业务护栏与失败语义

统一 MCP 管理负责配置和运行状态，风险插件不维护连接副本。MCP 协议 Session、服务凭据和业务主体分开；共享服务凭据不能证明上游已经按用户隔离。原生 MCP 连接 Header 是连接配置，不自动承载每次调用的人类身份；按业务主体隔离的上游接口必须使用经过验证的凭据选择或受控代理映射。采用 OAuth 时验证面向正确资源的 Token，不把入站 Token 无条件透传到下游。

每个已开放叶子操作执行前重新检查当前上下文，包含组合子步骤、OpenAPI、MCP 工具与资源以及异步等待后的派发。首期不开放定时任务或未纳管的后台执行器。代码变体同样调用受控执行入口，不得直接引入隐藏网络客户端绕过。上游收到的实际目标和身份绑定必须能验证；原始接口无法识别用户时，明确由受控代理验证的范围及原接口旁路限制。

需要业务确认的动作，确认绑定主体、Session／任务、Agent 来源、实例代次、工具、目标、参数摘要和许可版本。确认后重新验证信任、风险与授权；内容变更或过期使旧确认失效。身份失效或越权不能由人工确认变成有效许可。常规查询、报告和既有 AI 自动保存不因本规范增加无收益确认。

输入检查、计划检查、工具执行前检查和输出发布前检查分别声明覆盖阶段。首期选定报告通道时，向接收方发送前核对内容与权限；流式输出未经专门验证不能声明覆盖。风险检测结果不能替代报告正确性或 Harness Evaluation，不能要求读取隐藏思维作为控制依据。

| 状态 | 对外与执行行为 |
|---|---|
| 凭据缺失／失效、主体不受信、无基础权限 | 拒绝对应访问，原因码与用户可理解说明分开 |
| 必需风险事实未知／过期、规则或实例版本未同步 | 暂停或拒绝对应受保护动作；不能显示为低风险或已生效 |
| 授权插件异常／卸载 | 拒绝其负责的业务路径，不回退 owner 或不受限执行 |
| 已获准但尚未派发，期间发生撤权 | 使用最新许可检查，受限请求不发出 |
| 请求已发出后取消／撤权 | 尽力取消，记录完成、取消确认或未知；不承诺回滚 |
| 外部副作用未知 | 先查询实际业务状态，不能自动补发高副作用请求 |

记录最少必要的请求引用、主体引用、资源、动作、版本、原因、执行结果与覆盖。原始凭据、Token、Cookie、身份私钥和无关用户内容不进入普通日志、Run 或纠错记录。平台管理者可见诊断与业务用户可见提示分别裁剪，拒绝消息不能泄漏其他用户资源是否存在。

## 5. 插件一致性测试与交付要求

三类职责共用以下测试场景；测试依实际使用能力执行，不要求每个插件自建测试平台。

| 场景 | 必须观察的结果 |
|---|---|
| 凭据有效、过期、撤销、轮换及同人多凭据 | 稳定主体不变；失效拒绝；HTTP／WS／重连一致 |
| 不同来源同名用户，客户端伪造主体 | 不合并身份，不接受自报归属；受信断言不能跨接收实例复用 |
| Agent 签名认证失败、身份撤销或来源不匹配 | 分别拒绝；用户登录成功、人工确认或低风险不能放宽 |
| Agent 未开放或用户无权 | 两个判断分别生效；启动、发布或低风险不能绕过 |
| A、B 同共享 Runtime 操作会话、任务、文件与报告 | UI、Remote、事件、工具及下载均不串数据；历史未归属不自动认领 |
| 仅收紧 A 的写操作 | 查询继续，B 不变；每个组合叶子重验，受限请求没有到达上游 |
| 限制迟到、网络失联、到期、重启及解除 | 新版本不被旧版本覆盖，未确认可见，先同步再调用，解除后重算 |
| 插件失败、卸载、确认后变参及在途取消 | 拒绝／未知语义准确，旧确认失效，无 owner 降级或假称回滚 |
| 正常报告与无害合成敏感标记 | 正常业务完整；选定发布前检查在触达接收方前执行 |

开发交付须包含配置与兼容说明、真实注册及清理、上述受影响测试、覆盖／未覆盖清单和新进程／新 Session 装载证据。替身只替换外部服务边界；真实身份互信、真实业务和双用户实际隔离分别提供证据。具体 POC 只在 [07](07_关键POC验收与架构决策.md#business-control-poc)维护结果入口，规范存在不代表行为已验收。

核对日期为 2026-10-19。以下资料提供边界和协议依据，本规范是针对本平台的设计选择，不声称上游原生已具备完整多用户网关或所有工具隔离。

- [DSH rc.2 RemoteAccess](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/api/remote-access/README.md)：使用原生非 owner 授权接缝，平台补可信身份和业务归属。

- [MCP 2026-07-28 授权](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)、[工具规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)、[取消语义](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/cancellation)：作为本次设计调研依据，区分发现、实际许可及尽力取消。运行实现仍服从锁定 SDK 与服务端实际协商版本；不能将新版字段强加给当前旧版连接。
- [DSH rc.2 Connection](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/client/connection/README.md)、[工具注册与执行](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/core/tools/src/index.ts)：自定义业务传输创建真实非 owner Peer，工具可见性限制与真实执行 Guard 分别落实。
- [httpxy v0.5.5](https://github.com/unjs/httpxy/blob/v0.5.5/README.md)：HTTP／WS 转发候选；是否可用由本项目原生接缝 POC 决定，不自行实现完整代理协议。
