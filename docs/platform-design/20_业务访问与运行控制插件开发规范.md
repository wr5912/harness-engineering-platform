# 20｜业务访问与运行控制插件开发规范

本规范定义已选未来能力的开发合同，尚无对应通用插件实现。接入基线为 DSH `v0.2.1-rc.2`；平台和业务 Runtime 的实际升级结果以验收矩阵为准。系统边界见 [02](02_系统架构与部署设计.md#business-access-architecture)，事实写权见 [03](03_存储架构与数据契约.md#business-access-data)，业务过程见 [04](04_核心业务闭环与服务接口.md#business-gateway-flow)，实施顺序见 [05](05_实施路线与迭代计划.md#business-control-route)。本章唯一维护插件接口与一致性要求，不另建策略服务或资产副本。

## 1. 四类职责与执行责任

| 四字分类名 | 英文合同标识 | 必须完成的职责 | 不负责的决定 |
|---|---|---|---|
| **身份认证** | `authentication` | 验证当前凭据，输出已验证的身份声明及有效时间 | 不授予业务 Agent 或资源权限 |
| **身份信任** | `identity-trust` | 接受受信来源，映射稳定主体，核对有效状态与必要业务身份绑定 | 不把身份有效等同业务许可 |
| **风险评估** | `risk-assessment` | 对明确对象与动作生成有时效和依据的风险事实 | 不创造基础权限，不直接改共享 MCP 配置 |
| **访问授权** | `access-authorization` | 根据主体、动作、资源、归属及必要风险事实作允许／拒绝决定 | 不代替真实执行，不将低风险当作充分授权 |

四类职责可以独立替换，也可以由一个安装包提供多个服务；不要求四个进程、四套存储或每次串行四次远程调用。身份信任可向认证提供受信密钥和身份映射；风险评估可在入口、工具前或运行事件触发后异步更新事实。唯一授权适配器组合这些事实，访问执行点落实结果。

访问执行不是第五类决策插件。业务网关、DSH Remote 接入、工具管线、文件工具、MCP 转发、OpenAPI 与组合叶子在各自真实边界检查；任何点不得用前端隐藏、目录过滤或模型承诺替代。工具／目标／参数检查、必要确认和输出前检查属于对应业务执行阶段，各自声明覆盖，不能由某一个 Guard 推断全部生效。

## 2. 统一 TypeScript 合同

以下为待实现的公共合同，名称用于确定开发边界，不表示已有 RPC。实现时集中在一个可导出的 TypeScript 模块，由管理与 Runtime 适配器引用，不能各复制一份定义。字段中的 ID 均由受信服务器建立；普通调用者不能自行填入主体或归属。

```ts
type PluginKind =
  | 'authentication'
  | 'identity-trust'
  | 'risk-assessment'
  | 'access-authorization';

interface ControlPluginManifest {
  name: string;                 // 小写 kebab-case
  version: string;
  contractVersion: 1;
  kinds: readonly PluginKind[];
  dshCompatibility: string;
  capabilities: readonly string[]; // 实际支持的凭据、信号或执行阶段
}

interface Subject {
  id: string;                   // 稳定主体，不使用凭据值或显示名
  kind: 'human' | 'service';
  identitySource: string;
}

interface ControlScope {
  workspaceId: string;
  agentId: string;
  subjectId?: string;
  instanceId?: string;
  runtimeGeneration?: string;
  sessionId?: string;
  serverId?: string;
}

interface BusinessContext {
  requestId: string;
  subject: Subject;
  scope: ControlScope;
  sourceDigest: string;         // 实际业务 Harness 装载身份
  invocationId?: string;
}

interface ResourceRef {
  kind: string;                 // 已注册资源类型
  id: string;
}

interface AccessRequest {
  context: BusinessContext;
  action: string;               // Remote 方法或已注册业务动作
  resources: readonly ResourceRef[];
  validatedArgs?: unknown;      // 仅允许已校验、最小必要的参数
}

type AccessDecision =
  | { kind: 'allow'; policyVersion: string; restrictionVersion: number }
  | { kind: 'deny'; reason: string; policyVersion: string;
      restrictionVersion: number };
```

一个 Session 的所属人是人类主体，执行它的 Agent 是业务行为主体；两者不可混为同一个 `userId`。后台任务保留原可信归属和 Agent／来源，不依赖是否仍有浏览器连接。没有主体的内部原生调用也不能被解释为某个人类用户，必须在业务执行边界恢复真实任务上下文或拒绝。

范围字段必须与真实登记交叉核对，Session 属于指定 Agent、实例及主体，不能把互不相关的 ID 拼成有效上下文。风险范围中的可选字段是进一步限定，省略不表示调用者可以扩大范围。资源列表来自服务端解析，不能为空或包含未注册身份；参数按实际动作的类型校验，`unknown` 不是任意代码或未经检查的策略输入。

### 身份认证接口

```ts
interface IdentityEvidence {
  issuer: string;
  externalSubject: string;
  method: string;
  verifiedAt: string;
  expiresAt: string;
  credentialRef?: string;       // 不含秘密的专用引用
}

type AuthenticationResult =
  | { kind: 'authenticated'; evidence: IdentityEvidence }
  | { kind: 'missing' | 'unsupported' | 'invalid' | 'unavailable'; reason: string };

interface AuthenticationInput {
  transport: 'http' | 'websocket' | 'callback';
  method: string;
  path: string;
  headers: Readonly<Record<string, string | undefined>>;
}

interface AuthenticationPlugin {
  authenticate(input: AuthenticationInput, signal: AbortSignal): Promise<AuthenticationResult>;
}
```

`AuthenticationInput` 由凭据传输适配器提供，只暴露该机制需要的 Cookie、Header 或回调材料；原始值不得进入共享业务上下文和普通日志。首个参考实现支持个人 API Key／Bearer Token，浏览器可换取受控会话；SSO 是可替换提供方，不是首期额外平台。多个机制有重叠时按配置选定的优先级处理；已识别凭据无效时不得尝试匿名或弱机制放行。Token 不能仅解码不验证，应按机制检查签名或服务端状态、来源、受众、有效期与撤销。

### 身份信任接口

```ts
type TrustResult =
  | { kind: 'trusted'; subject: Subject; trustVersion: string; expiresAt: string }
  | { kind: 'untrusted' | 'unknown'; reason: string };

interface IdentityTrustPlugin {
  resolve(evidence: IdentityEvidence, signal: AbortSignal): Promise<TrustResult>;
}
```

外部来源与外部主体的组合映射到稳定主体，不能按邮箱、昵称、客户端 `userId` 自动合并。凭据轮换及多个个人凭据不改变资源归属；多人共用一把 Key 只能形成同一主体，不能声称已区分不同的人。涉及业务 Agent 身份时，另核对固定业务来源、实例代次、受信注册回执及有效期；同名重建不继承旧核验。提供方不可达、未接入、失效和未知分别表达。

### 风险评估接口

```ts
interface RiskFact {
  id: string;
  version: number;
  scope: ControlScope;
  status: 'assessed' | 'unknown';
  signals: readonly { code: string; value: string; reason: string }[];
  source: string;
  observedAt: string;
  expiresAt: string;
}

interface RiskAssessmentPlugin {
  assess(request: AccessRequest, signal: AbortSignal): Promise<RiskFact>;
}

interface AccessAuthorizationPlugin {
  decide(request: AccessRequest): AccessDecision;
}
```

风险信号及可解释值由具体检测能力声明，不规定通用分数或擅自映射全部业务。超时、缺数据、覆盖不足、插件卸载与无法判断都保留未知；`assessed` 只表示完成对应范围的评估，不表示安全。配置为必需的事实缺失／过期时暂停或拒绝其保护动作，不自动解除限制。恢复需要重新评估并重新计算全部约束。

授权决策同步读取当前内存中的已核对事实与归属；需要异步评估的入口先完成 `assess` 和事实应用，再调用授权。每次真实派发核对当前限制版本，不把上一次允许当作永久票据。许可、限制、事实版本及归属的保存合同由 [03](03_存储架构与数据契约.md#business-access-data)维护。

## 3. DSH 装载与原生接入

- 使用 TypeScript 与 Cordis `Service`／`inject`，遵守注册、依赖就绪、卸载和 `dispose`。插件清单注明合同版本、兼容范围、实际覆盖和配置 Schema；缺依赖或配置不合法时明确失败，不隐式跳过控制。
- 网关使用隔离的业务监听和认证服务，不替换父平台的 Connection／owner 认证。注册 HTTP 与 WS 的同时登记清理器，卸载和撤权处理已有长连接；删除路由只阻止新握手。
- 实例接收经过认证的受信上下文并创建非 owner Peer。业务用户永远不转换为共享 owner。调用上下文用于承载身份，Session 归属存储用于持久所有权，两者缺一不可。
- 一个业务 Principal kind 只注册一个原生 `registerPolicy`；各插件向统一授权适配器提供事实。原生 `bindings()`、condition 与 `explain()` 为同步读取，不能直接返回 Promise 或在其中做网络风险分析。事实变化、撤销和到期时调用 `invalidate`，使原生快照及页面重读。
- 声明每个 Remote 方法涉及的全部资源。列表、搜索和流逐项检查；不能给业务主体宽泛 `global` 动作以替代对象归属。事件授权不自动裁剪载荷，因此只发送获准且不会夹带其他用户数据的事件。
- 原生权限快照只辅助界面；调用仍服务端检查。非 owner 页面注入对应快照，不能沿用默认 owner baseline。内存失效通知与跨实例分发是不同机制，跨实例仍需版本、回执与恢复快照。
- Exact Fetch 和插件自注册 HTTP 路径不自动经过原生 Remote 授权；逐路声明并检查，未支持路径保持拒绝。非 owner 原生交互参与仍有限制，必要确认必须验证专用接缝，不能临时提升 owner。
- 原生 `tools.restrict()` 约束继承的工具集合，当前作用域自己注册的工具仍可见；不能靠该掩码保证 MCP 撤权。工具注册、发现与重连都受相同能力上限约束，实际执行使用不可放宽其他拒绝结果的 `tools.guard()`，异步风险评估在它之前完成；排队或异步等待之后、实际网络派发之前再核对当前许可。
- 工具 Guard、文件、Shell、插件内部请求及代码变体不会因 RemoteAccess 自动获得读取隔离。每个已开放执行器取得真实 Session／任务上下文，并在执行前核对资源、目标与参数。受控工作目录和只读 Harness 不表示其他用户 HOME 不可读。
- 原生 `allows()` 在 owner 或 Remote 调用之外的允许结果不能作为模型工具的业务授权。内部执行器使用受信 `BusinessContext` 调用统一授权服务，不能因后台没有浏览器 Peer 而放行。定时任务到期时重新核对已保存主体及任务执行许可；主体撤销或许可失效后暂停后续受保护动作，不依赖创建时的一次许可。

## 4. MCP、业务护栏与失败语义

统一 MCP 管理负责配置和运行状态，风险插件不维护连接副本。MCP 协议 Session、服务凭据和业务主体分开；共享服务凭据不能证明上游已经按用户隔离。原生 MCP 连接 Header 是连接配置，不自动承载每次调用的人类身份；按业务主体隔离的上游接口必须使用经过验证的凭据选择或受控代理映射。采用 OAuth 时验证面向正确资源的 Token，不把入站 Token 无条件透传到下游。

每个叶子操作执行前重新检查当前上下文，包含组合子步骤、OpenAPI、MCP 工具与资源、重试、排队、定时任务和模型外的插件调用。代码变体同样调用受控执行入口，不得直接引入隐藏网络客户端绕过。上游收到的实际目标和身份绑定必须能验证；原始接口无法识别用户时，明确由受控代理验证的范围及原接口旁路限制。

需要业务确认的动作，确认绑定主体、Session／任务、Agent 来源、实例代次、工具、目标、参数摘要和许可版本。确认后重新验证信任、风险与授权；内容变更或过期使旧确认失效。身份失效或越权不能由人工确认变成有效许可。常规查询、报告和既有 AI 自动保存不因本规范增加无收益确认。

输入检查、计划检查、工具执行前检查和输出发布前检查分别声明覆盖阶段。首期选定报告通道时，向接收方发送前核对内容与权限；流式输出未经专门验证不能声明覆盖。风险检测结果不能替代报告正确性或 Harness Evaluation，不能要求读取隐藏思维作为控制依据。

| 状态 | 对外与执行行为 |
|---|---|
| 凭据缺失／失效、主体不受信、无基础权限 | 拒绝对应访问，原因码与用户可理解说明分开 |
| 必需风险事实未知／过期、规则或实例版本未同步 | 暂停或拒绝对应受保护动作；不能显示为低风险或已生效 |
| 授权插件异常／卸载 | 拒绝其负责的业务路径，不回退 owner 或不受限执行 |
| 已获准但尚未派发，期间发生撤权 | 使用最新许可检查，受限请求不发出 |
| 请求已发出后取消／撤权 | 尽力取消，记录完成、取消确认或未知；不承诺回滚 |
| 外部副作用未知 | 先查询实际业务状态，不能自动补发高副作用请求 |

记录最少必要的请求引用、主体引用、资源、动作、版本、原因、执行结果与覆盖。原始凭据、Token、Cookie、身份私钥和无关用户内容不进入普通日志、Run 或纠错记录。平台管理者可见诊断与业务用户可见提示分别裁剪，拒绝消息不能泄漏其他用户资源是否存在。

## 5. 插件一致性测试与交付要求

四类实现共用以下测试场景；测试依实际使用能力执行，不要求每个插件自建测试平台。

| 场景 | 必须观察的结果 |
|---|---|
| 凭据有效、过期、撤销、轮换及同人多凭据 | 稳定主体不变；失效拒绝；HTTP／WS／重连一致 |
| 不同来源同名用户，客户端伪造主体 | 不合并身份，不接受自报归属；受信断言不能跨接收实例复用 |
| Agent 未开放或用户无权 | 两个判断分别生效；启动、发布或低风险不能绕过 |
| A、B 同共享 Runtime 操作会话、任务、文件与报告 | UI、Remote、事件、工具及下载均不串数据；历史未归属不自动认领 |
| 仅收紧 A 的写操作 | 查询继续，B 不变；每个组合叶子重验，受限请求没有到达上游 |
| 限制迟到、网络失联、到期、重启及解除 | 新版本不被旧版本覆盖，未确认可见，先同步再调用，解除后重算 |
| 插件失败、卸载、确认后变参及在途取消 | 拒绝／未知语义准确，旧确认失效，无 owner 降级或假称回滚 |
| 正常报告与无害合成敏感标记 | 正常业务完整；选定发布前检查在触达接收方前执行 |

开发交付须包含配置与兼容说明、真实注册及清理、上述受影响测试、覆盖／未覆盖清单和新进程／新 Session 装载证据。替身只替换外部服务边界；真实身份互信、真实业务和双用户实际隔离分别提供证据。具体 POC 只在 [07](07_关键POC验收与架构决策.md#business-control-poc)维护结果入口，规范存在不代表行为已验收。

核对日期为 2026-10-19。以下资料提供边界和协议依据，本规范是针对本平台的设计选择，不声称上游原生已具备完整多用户网关或所有工具隔离。

- [DSH rc.2 RemoteAccess](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/api/remote-access/README.md)：使用原生非 owner 授权接缝，平台补可信身份和业务归属。
- [DSH rc.2 文件沙箱](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/fs/fs-sandbox/README.md)：读取边界需另行验证，不能从写入限制推断隔离。
- [NIST 数字身份指南](https://pages.nist.gov/800-63-4/sp800-63.html)、[NIST SP 800-207](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-207.pdf)：借鉴认证、可信来源和授权／执行分责，不照搬完整零信任基础设施。
- [Bearer Token](https://www.rfc-editor.org/rfc/rfc6750)、[JWT 校验](https://www.rfc-editor.org/rfc/rfc9068#section-4)、[Token 状态查询](https://www.rfc-editor.org/rfc/rfc7662)：按所用认证方式落实凭据验证和生命周期。
- [MCP 2026-07-28 授权](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)、[工具规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)、[取消语义](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/cancellation)：作为本次设计调研依据，区分发现、实际许可及尽力取消。运行实现仍服从锁定 SDK 与服务端实际协商版本；不能将新版字段强加给当前旧版连接。
- [DSH rc.2 Connection](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/client/connection/README.md)、[工具注册与执行](https://github.com/deepseek-ai/deepseek-harness/blob/687f282e8625c6b8d11ff58211a90524be2e4317/packages/core/tools/src/index.ts)：自定义业务传输创建真实非 owner Peer，工具可见性限制与真实执行 Guard 分别落实。
- [httpxy v0.5.5](https://github.com/unjs/httpxy/blob/v0.5.5/README.md)：HTTP／WS 转发候选；是否可用由本项目原生接缝 POC 决定，不自行实现完整代理协议。
