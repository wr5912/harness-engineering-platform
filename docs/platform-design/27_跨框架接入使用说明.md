# 跨框架智能体接入使用说明

本功能将保留原 Runtime 的已有智能体登记到平台，通过统一入口调用，并为明确选择的资源提供实例机器授权。原系统仍负责部署、升级、启停和恢复；“停用入口”与“移除登记”不停止远端进程。平台管理助手和默认 Harness 继续使用 DSH。

## 登记与访问

在“实例管理 → 接入实例”选择“登记已有智能体”，在一个表单中填写登记信息，其他选填或沿用配置的项目放在默认折叠的“更多设置”中。可关联已有登记智能体；同一逻辑智能体可有多个实例。

表单的星号`*`表示完成接入、验证启用时必填，并有对应的必填语义。OpenCode首屏为名称、框架、服务地址3项；AgentScope增加原服务的Agent ID，共4项；DSH增加工作区ID和Agent Preset，共5项。DSH页面将两个字段转换为原生选择器JSON，无需手写JSON。可以只填名称先“保存登记”，稍后编辑并补齐连接，草稿不开放入口。

“选填”允许不填写；“默认”说明未自定义时使用的实际值：实例名沿用智能体名称，所属系统取首次保存时服务地址的主机名，责任主体为平台管理者，入口默认仅允许`platform-owner`。关联或编辑已有对象时沿用其公共信息与当前访问范围，补地址或验证重试不会改写公共名称、所属系统及责任主体。清空允许主体或移除`agent:access`后不能启用，页面会指出并聚焦对应字段。

“保存登记”可保留草稿，不开放业务。“验证并启用”需要目标验证与当前授权一致。连接结果附观察时间，不表示持续在线；改目标、认证材料或适配方式后重新验证。默认共享使用范围应与实例资源权限一致，平台 Session 归属检查不等于上游工作区或记忆已私有隔离。

| 框架 | 本期接入方式与目标选择器 |
|---|---|
| DSH rc.5 | 原生 Session API；selector 为包含 workspaceId、agentPreset 的 JSON，使用原生实际 ID |
| AgentScope Python 2.0.8 | 原生 Service API 与 Session SSE；selector 为实际 agent_id |
| OpenCode 2.2.5 | 原生 /api 服务与按权威 Session 封套过滤的事件；selector 为可选固定工作目录 |

接入实例 API 页提供创建、发送和读取结果。上游“已受理”不代表执行完成；中断或超时后先读取状态。首期未为接入实例提供完整原生 Web/WS 代理、任务取消、远端进程控制或用户委托；既有托管 DSH Web 不因此改变。

上游凭据由管理者放在数据根 `.local/credentials/external/<引用>.json`，内容为 `{ "headers": { "Authorization": "<目标原生凭据>" } }`；DSH 原生服务可使用其自己的 Cookie。“凭据引用（选填）”只表示表单不统一强制该字段，原服务要求认证时仍须配置并填写有效引用，不能因此按匿名访问。仅从此专用来源构建上游请求，不透传平台用户 Cookie 或伪造身份头。引用文件的认证材料变化会使旧验证失效。不要将凭据写入 endpoint、说明或普通日志。

保存、验证或启用的响应丢失时，先“核对保存结果”；核对使用实际在途阶段的请求标识，显示服务端当前入口状态。待核对期间草稿不能修改或重新提交，关闭再打开也保留核对状态；回读不会重复执行或自动继续启用。

## 实例身份与指定资源

详情“接入与能力”显示实例身份，“访问授权”分别维护用户入口与 Harness 签名资源权限。创建或轮换实例凭据只在专用流程交付一次秘密；关闭后通过状态核对，需要时重新轮换，不从普通详情找回。正常凭据有效期为30天，轮换重叠窗口10分钟；泄漏时直接撤销旧凭据。

管理者先在业务访问配置的 agentAccess 中设置 issuer、受众和固定资源工具映射；当前资源配置由该文件维护，UI对已登记资源授予权限。每个资源定义固定 endpoint、原生 credentialFile、工具 name/scope/method/path/inputSchema 及可选 objectField。授予维护实例、资源、scope和对象范围。留空对象范围表示该资源内所有对象，应按实际需要收窄。

connector 独立持有实例 key，按需领取短期 token，仅连接已配置资源；不向模型提供“复制签名”或“领取 key”工具。示例启动入口为 `node platform/plugin/lib/agent-access-connector.js <专用配置文件>`。配置字段和执行校验见[接口合同](04_核心业务闭环与服务接口.md#cross-framework-access)。

停用用户入口、撤销实例 key、禁用资源授予分别操作。资源撤销不停止实例，也不关闭其他原认证工具。认证状态只证明本次凭据持有及所列证据，不证明代码完整、实例健康或所有调用已授权。

## 模拟远程实例与复现

样本源码在 `~/work/cross-framework-sources/`，AgentScope可复用经过审读的既有锁定源码。源码、依赖锁与运行身份需核对；不自动执行未清点的 Hook、安装脚本或默认工具。本仓库 `platform/cross-framework/` 保存 TS 部署编排、模拟资源与验收脚本；所有运行状态在关联数据根 `.local/cross-framework-samples/`，不进入托管实例列表。

- `serve.mts <隔离数据根> [监听地址]` 启动仅用于验收的身份、业务资源、确定性模型及统一入口；必须选择 `.local` 下独立目录。源码运行使用 Node24 的 `--experimental-transform-types`，发布代码使用构建制品。
- `dsh-setup.mts`、`agentscope-setup.mts`、`opencode-setup.mts` 配置各自真实上游接口、原生会话、独立 connector 与资源授予；运行前按脚本参数和实际端口核对，不改正式配置。
- 框架资源并存脚本分别查询原生工具结果和平台记录，不能用模型回复替代工具执行结果。样本模型为确定性协议模拟，不用于业务质量比较。
- `compose.mts project <样本状态根>` 生成不可编辑的 Compose 投影并校验；恢复使用同入口 `recover`，只处理校验归属的样本容器，保留 HOME、状态、端口与秘密引用。Compose 投影不能替代源码和凭据备份。

本轮是本机真实 Runtime 模拟远程已有实例、模拟模型和模拟业务资源的技术验收。真实异地主机、真实模型效果、真实业务服务及生产部署均不由此推导。实际通过、失败及未验证项只在[项目验收矩阵 PA-14](../ai-agent-harness项目验收矩阵.md#pa-14-跨框架接入与安全访问)维护。

## 故障与恢复

入口不可用时先核对登记修订、目标认证材料、入口开关和最近验证；不要通过development或管理凭据绕过。签名工具失败时分别查看凭据、授予、kid及对应调用记录，其他服务继续按原认证使用。结果未知时读取原生Session或目标端账本，不重放可能产生副作用的请求。

备份至少覆盖登记与策略、专用上游凭据、签发身份、实例凭据及撤销状态、必要Session映射和访问记录。恢复程序与配置使用兼容版本，重启后重新观测连接；普通平台离线包排除.local，不能代替此恢复清单。

## 当前主机的平台 Runtime

本轮正式平台保留原数据根和平台HOME，通过锁定源码构建的DSH rc.5运行；系统全局`/opt/dsh`仍为rc.2。当前主机的项目本地入口`.local/cross-framework/runtime-bin/dsh`链接到`~/work/cross-framework-sources/dsh/apps/cli/lib/bin.js`，依赖同一源码树的构建与Node24。执行平台prepare或后续启停前，先在该终端选定这一入口并核对版本：

```sh
cd /home/admin/work/harness-engineering-platform
export PATH="$PWD/.local/cross-framework/runtime-bin:/home/admin/.config/nvm/versions/node/v24.19.0/bin:$PATH"
export HARNESS_PYTHON=/usr/bin/python3.10
dsh --version
platform/dsh-platform status
```

这里的`dsh --version`应为`0.2.1-rc.5`。启动器通过PATH选择DSH并执行精确版本核对；仅设置`HARNESS_DSH_ENTRY`不会切换CLI。源码目录与本地入口属于当前主机运行依赖，迁移时按锁定来源重新准备，不能只复制链接。

平台更新仍先核对原生热装载。原生HMR重组不会重新读取CLI `--patch`文件；当prepare改变生成Profile overlay中的扩展路径时，须核对无在途任务后定向重启，复用原HOME并再次核验实际模块路径、旧Session和受影响RPC。当前进程与实测结论见[工程验收](../../platform/plugin/test/evidence/cross-framework-20261102/README.md#正式平台装载)，不在使用说明维护易变PID。

仅更新现有`client.js`时，使用原生客户端HMR：原子替换完整客户端制品后，原生监视器默认每500ms检查文件变化并发布新模块revision，再刷新页面核对实际界面。无需为纯界面变化重新prepare或重启；客户端revision、制品摘要与服务端保持情况分别留证。
