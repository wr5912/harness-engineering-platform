# 第三方访问控制接口协议

协议版本：1.0。

本规范用于第三方统一维护基础工具权限和运行时条件策略。平台按真实业务请求调用服务，服务结合当前策略及风险评估结果，返回本次允许、禁止或确认决定；平台在实际派发点执行结果，不运行第三方返回的代码。

访问控制页的“查看接口规范”和“下载接口规范”共用本文件。第三方服务优先；无配置或无法提供有效决定时使用手动兜底策略，明确禁止属于有效决定，不触发兜底绕过。

## 传输与配置

平台配置项为 `accessAuthorization`，包含 `endpoint` 和可选 `timeoutMs`；存在表示启用第三方访问控制，移除表示使用手动策略。该服务独立于风险评估开关；关闭风险评估时仍查询第三方基础授权。

使用 HTTP `POST`、`application/json`、UTF-8。默认超时1500毫秒，可配置1–60000毫秒，调用服从原请求取消信号。地址不夹带凭据、查询参数或片段；本版本不提供任意认证Header表单。需要额外接入认证的部署通过既有受信网络或服务前置接入层接入。HTTP响应探测不能证明授权合同通过。

第三方调用可发生在平台或业务Runtime。配置地址须从实际执行环境可达；容器中的`127.0.0.1`表示容器自身。管理页探测只证明平台侧HTTP响应，不能替代业务容器的POST接入与实际执行核对。

## 请求

```json
{
  "protocolVersion": 1,
  "requestId": "00000000-0000-4000-8000-000000000001",
  "binding": "由平台生成的本次请求SHA-256摘要",
  "scope": {
    "workspaceId": "workspace-example",
    "agentId": "example-agent",
    "subjectId": "subject-example",
    "instanceId": "example-instance",
    "runtimeGeneration": "generation-example",
    "sessionId": "session-example",
    "serverId": "example-mcp"
  },
  "sourceDigest": "sha256:example",
  "operation": {
    "serverId": "example-mcp",
    "operationId": "update_asset",
    "kind": "write",
    "target": "https://service.example/assets/123",
    "method": "POST"
  },
  "input": { "assetId": "123", "status": "reviewed" },
  "resources": [],
  "risk": { "enabled": false, "status": "disabled", "facts": [] }
}
```

| 字段 | 要求与含义 |
|---|---|
| `protocolVersion` | 固定整数`1`。 |
| `requestId` | 平台为每次访问决策生成的唯一请求标识。 |
| `binding` | 平台为主体、完整范围、来源、真实操作、输入及资源生成的摘要；服务原样回显，不重新拼接。 |
| `scope` | 实际工作区、智能体、主体及实例、代次、会话、MCP服务，不能由前端任意指定。 |
| `sourceDigest` | 当前智能体的实际来源。 |
| `operation` | 服务端解析的真实服务、工具、类型、目标、方法，以及可选`schemaDigest`。服务对这些事实决定权限，不替换执行目标。 |
| `input` | 当前操作参数，未提供时为`null`。 |
| `resources` | 当前操作涉及的平台资源引用，元素为`{kind,id}`，无引用时为空数组。 |
| `risk.enabled` | 是否配置并启用风险评估。 |
| `risk.status` | `disabled`：未启用；`assessed`：存在本次可用评估；`unknown`：缺少确定依据；`unavailable`：服务无法提供有效结果。 |
| `risk.facts` | 本次适用的风险事实。各事实包含身份、范围、版本、级别、信号、来源、观察时间与有效期，必要时包括场景／标签及操作绑定。对外`source`只提供HTTP(S)公开origin，其他来源统一为“第三方风险评估”；不传递风险服务URL中的凭据、路径、查询或片段。内部事实和绑定保持原值。没有有效事实时为空；取得新评估失败但仍有适用的未过期事实时，状态可为`unavailable`而数组保留这些已有依据及其观察时间。不能把空数组解释为低风险。 |

独立部署风险和访问服务时，提供方须约定相同的场景代码、操作标签及其含义。平台按实际字段和范围传递，不自行分类，也不因报文合规就宣称两个服务的业务语义已互通。

所有标识、摘要、范围和风险状态由平台取得，操作者不填写这些内部字段。第三方服务维护实际权限和条件策略；平台不要求再复制一份同等规则进行正常授权。

## 响应

`allow`、`deny`和`confirm`均使用成功HTTP状态（通常为200）返回以下规范JSON。业务禁止由`decision: "deny"`表达；不能仅返回HTTP403表示业务禁止，因为非成功HTTP状态表示服务不能提供规范决定，会触发手动兜底。

```json
{
  "protocolVersion": 1,
  "requestId": "00000000-0000-4000-8000-000000000001",
  "binding": "与请求完全相同的摘要",
  "decision": "confirm",
  "policyVersion": "policy-42",
  "reason": "本次敏感写入需要使用者确认",
  "expiresAt": "2099-01-01T00:00:00.000Z"
}
```

| 字段 | 要求 |
|---|---|
| `protocolVersion`、`requestId`、`binding` | 必填，必须与请求完全相同。 |
| `decision` | 必填，`allow`、`deny`或`confirm`。 |
| `policyVersion` | 必填，第三方实际使用的非空且无首尾空白的策略版本，最多256字符。 |
| `reason` | 必填，非空用户可理解的依据，最多1000字符，不包含凭据。 |
| `expiresAt` | 必填，收到响应及最终派发时仍有效的UTC ISO 8601字符串，格式为`YYYY-MM-DDTHH:mm:ssZ`或带1–3位毫秒后缀再接`Z`。示例远期时间仅说明格式。 |

`allow`允许本次请求进入平台最终核对；`deny`拒绝本次请求；`confirm`调用DSH现有确认能力。所有决定仅对当前绑定有效，不授予智能体永久权限，不自动重放或批量执行其他请求。

确认结束后，平台重新核对身份、风险、策略和本次操作；不能沿用已经过期、目标变化、参数变化、被撤销或版本变化的允许。结果等待期间发生原请求取消时停止处理。

## 第三方优先与手动兜底

| 情况 | 行为 |
|---|---|
| 有效`allow` | 第三方决定优先；继续核对真实目标、身份、归属及人工临时限制。 |
| 有效`deny` | 直接拒绝，不运行手动策略寻找另一条允许。 |
| 有效`confirm` | 使用原生确认，确认后按当前条件重新判断。 |
| 未配置第三方 | 执行已保存的手动基础范围、工具默认处理与条件规则。 |
| 超时、连接失败、非成功HTTP状态、非法JSON、版本或绑定不匹配、无效字段、收到时已过期 | 标明第三方不能提供有效结果，按手动配置兜底；不静默显示为第三方允许。 |
| 无有效风险依据 | 外部服务收到明确风险状态；进入手动兜底时，执行基础处理与纯工具规则，暂停依赖风险／场景／标签的条件。 |
| 原业务请求取消 | 停止等待与派发，不以兜底继续执行已经取消的请求。 |

服务可动态调整工具基础范围以及风险、业务场景和危险／敏感操作的处理。第三方有效结果取代同一请求的手动工具策略；手动配置作为不可用时的兜底，默认从辅助入口维护。平台原生能力边界、可信身份、业务归属、实际工具目标与人工临时限制继续生效，第三方不能使不存在的工具可执行或转移请求目标。

每次受管操作在实际派发前取得并核对本次决定；没有整份规则下载到客户端作为可编辑副本。界面回执展示本次来源、结果、原因、策略版本及有效期，历史回执不能冒充当前许可。服务恢复影响后续请求；已经到达上游的动作不能据此保证撤回。

开发调试实例沿用既有放行语义，平台管理身份使用DSH原生能力。更改第三方协议或配置不等于既有业务容器已装载新的程序版本。

## 接入核对

至少核对允许、禁止、确认、不可用手动兜底和兜底拒绝；验证风险关闭后第三方基础授权仍执行、风险不可用不会伪装成低风险、跨会话／参数／目标绑定失配、取消和确认期间策略变化。核对每个真实MCP叶子及受管报告路径，确认拒绝请求没有到达上游。隔离HTTP夹具只证明技术闭环，真实第三方业务判断效果需使用实际服务另行验证。
