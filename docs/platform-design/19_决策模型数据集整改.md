# 决策模型数据集审查与整改

本次任务审查并整改“请 AI 抽取决策样本”，范围包括平台接口、样本编辑与导出，以及平台管理助手实际装载的业务 Harness。当前合同仍由 [03](03_存储架构与数据契约.md#当前决策样本与结构化阅读)维护；本文记录审查依据、实施顺序和验证结论，不另维护一份数据 schema。

## 审查基准与外部依据

开始前已获取程序仓所有配置远端的分支引用，远端只有 main；当前程序基准为 `b8a45b4beb2ce852eb21f5159421e9bf1f6f6096`。数据仓也已获取远端引用，基准为 `6753070a55e2a885d6e851736f53de281b82377a`。程序原有 17 个未跟踪文件、数据仓原有 6 项已跟踪修改及 2 项未跟踪资产均不属于本次整改。

参考 [LocalLLaMA/typed-decisions](https://huggingface.co/datasets/LocalLLaMA/typed-decisions/tree/7189f46b02248bd2569df7325c9df8e3b24e90a7)，锁定版本为 `7189f46b02248bd2569df7325c9df8e3b24e90a7`，许可证为 Apache-2.0。本轮核对了该版本的数据卡及安全事件子集的一条实际结构。借鉴的是可见状态、命名问题、类型与规则、监督分布、来源和用途的组织方式，不导入整套数据或复制排行榜。

该参考集将 `state` 和 `questions` 作为模型输入，同一状态可对应多个决策题，题型为 `choice`、`noul`、`score`。候选或等级的文字定义属于输入；`gold` 是监督目标，构造信息与标注一致性不属于输入。其教师多次采样结果并不等于人工真值。平台无需机械要求每条五题，也不为覆盖客服、发票等名称而编造本地业务资料。

## 已确认的问题

| 问题 | 当前证据及影响 | 整改落点 |
|---|---|---|
| 评分对象不在模型输入中 | 已有真实 reviewed 样本要求评价“这条回复”，回复正文仅在审核元数据，`state` 中没有该回复；输入不足以回答问题 | 消除 Skill 对事后回复评分的歧义；新版显式区分监督语义，逐题检查输入可答性；旧记录不自动升级 |
| 单个问题槽和硬标签限制 | 后端与 UI 固定 `questions.decision`；无法表达同一业务状态的多个命名决策及软标签 | 版本化合同、命名问题映射、输入与目标分离、workflow/task 与逐题标签来源 |
| 来源校验只覆盖 trace 字节 | Case 归属、角色与采集状态还依赖其他 Run 文件；保存、复核和训练导出未统一重验 | 固定真实来源集合；共享来源合法性、决策切片和 state 一致性检查 |
| 可编辑组名能绕过留出 | 人工改 group 后可擦除已知同源关系；未分配样本默认进入训练 | 固定来源组，人工分组只能合并关联；显式用途导出，未分配不自动训练 |
| 读取与导出过浅 | 没有格式版本，主要校验 question，来源失效和损坏 state 仍可能进入训练 | 深校验和逐条资格说明；旧格式只读保留，不静默重写 |
| 人员复核缺少逐题语义 | 单段 JSON 与一个综合勾选框，原动作、建议和人工标签易混淆；跨批次阻塞原因不可见 | 多题编辑、逐题复核与输入可答性声明；资格由服务端计算，页面复用 |
| 管理指令与实现相互限定 | 数据侧 Skill 和方法均固定旧单题格式，并存在事后评分歧义 | 同步修改数据侧实际 Skill 与方法；程序只提供执行合同，不恢复程序内业务 Skill 副本 |

现有固定 Run、决策前切片、真实请求与 reconstructed 区分、原生确认、乐观锁、AI 建议不得自批、同任务分组等机制继续使用。抽取不要求或生成模型私有思维链；标注依据只记录可核对的外显证据。

## 实施方案

1. **统一新版合同。** 新批次声明格式版本 2。一条样本共享服务器生成的 `state`，记录真实业务 `workflow`、`task.id` 与监督语义，支持一个或多个稳定命名的问题。`questions` 仅含类型、问题和候选/等级规则；`targets` 分别保存标签、可选概率、来源、依据、复核状态与输入时点声明。模型产生的标签始终是建议，不因 Run 成功或软标签格式而成为人工真值。
2. **验证标签和证据。** 三题型分别检查标签类型、候选键、等级和概率覆盖、范围与归一性；硬标签不自动补成 100% 概率。声明教师采样或分布聚合时必须有对应来源，不把一次建议包装成多次采样或校准结果。每题说明其监督目标是观察到的行为还是基于可见状态的推荐判断，不将二者混用。
3. **统一来源检查。** 预览固定参与 Run 身份、角色、Case 归属、采集状态和 trace 判断的必要来源摘要。保存、人员复核和合格导出使用同一验证入口，重新定位决策和输入。来源缺失、改变或输入不一致时给出明确原因，保留可阅读的候选事实，阻止其作为合格训练或评测样本导出。
4. **固定已知分组。** 来源任务组由服务器建立且不可任意修改；人员可合并相关任务，不能通过改名擦除已知同源关系。训练、开发、校准、测试之间按固定来源组和人工关联组共同检查。只有显式 `train` 可作训练导出，`unassigned` 留待决定；已复核留出集有独立下载入口。
5. **完善复核页面。** 展示业务任务、多个命名决策、三题型规则、实际观察、标签来源和审核依据。修改题目、规则或目标后撤销受影响题目的复核。展示服务端计算的可导出数与阻塞原因；复用现有轨迹查看能力定位原始来源，返回时保留草稿。旧格式明确只读及重新抽取提示，候选下载不与训练下载混称。
6. **整改管理 Harness。** 直接修改数据仓独立工作树中的抽取 Skill 和对应研究方法，不修改无关 Agent 或虚构管理 Agent/Experiment。先读取当前程序合同和真实源状态，再建立行业问题与候选；材料不足时区分“无法标注”与“补证、升级、暂停本身就是业务决策”。没有可见回复时禁止评价该回复；没有真实概率证据时保留硬标签或建议，不制造概率正确性。程序入口、工具说明、提案和原生作用域与新合同同步。
7. **处理旧资产。** 不更改已有 Run、原始 trace、历史 reviewed 样本或旧研究结论。旧格式继续可读和候选导出，但不能直接升级成新版合格训练记录；通过已有重新抽取入口建立新批次。程序和数据工作树各自保留可审查差异，未经本次任务明确要求不提交、推送或替换正式服务。

## 验证与完成条件

| 层面 | 必须核对的行为 |
|---|---|
| 后端合同 | 同 state 多命名题；三题型硬/软标签；非法概率、缺失键、非有限数、来源伪造拒绝；新旧格式明确区分 |
| 来源与分组 | 预览后身份文件改变、保存后来源失效、输入被改、同源改组、跨批次留出均不能绕过；合格导出只含显式用途与已复核题目 |
| 页面 | 固定 Run 与任务、逐题编辑复核、来源定位、并发冲突保留草稿、刷新回读、候选与训练/留出下载；1440/390px 主路径可用 |
| 管理 Harness | 新 Session 实际装载新 Skill；工具和动作作用域仍固定；正常业务状态生成多题，缺证不乱贴标签，不可见回复评分反例被拒绝；预览、确认保存和回读一致 |
| 既有能力 | 原生确认、真实请求/reconstructed 区分、Run 不可变、决策样本之外的变体与评测路径无直接回归 |

可用真实 Run 提供输入，但确定性夹具、UI 测试和少量模型观察分别记录，不将它们互相替代。概率校准、行业真值、全行业覆盖和模型训练收益不属于本轮已经证明的效果；需要真实领域标注和独立比较后才能形成结论。
