# 任务型智能体交付与验收

平台以“描述业务需求，得到可使用的智能体及可核对的结果”为目标。当前管理助手直接使用 DSH 原生会话、权限和领域工具，不再提供额外交付任务执行器、任务卡或平台总额度。当前会话与数据合同见 [03](03_存储架构与数据契约.md#task-delivery-contract)，操作流程见 [04](04_核心业务闭环与服务接口.md#task-delivery-interfaces)。

以下保留 2026-10-16 交付任务机制的历史实施与验收证据，涉及任务预算、修复轮数、任务恢复、交付探针和卡片的记录不代表当前实现；历史失败和限制不改写。当前验证状态见项目验收矩阵。

## 验收方法

业务资产和比较输入在运行前固定。每次评测保存原始 Run、实际来源、镜像、模型、工具轨迹与产物；失败和缺证据均保留。模型自评只作为辅助，巡检设备集合、报告数量、工具调用和实际下载另行核对。评测容器与交付实例具有不同 HOME，交付时在最终实例的新 Session 中重新执行代表业务输入，核对该实例自身生成的报告。

三轮修复、助手请求数与截止时间由任务后端控制，暂停和恢复不重置额度。评测及交付探针的真实请求尝试分别累计，缺失轨迹、失败或在途消耗不能按零处理。当前容器内单次评测不支持跨角色请求数的实时硬封顶；只能读取实际消耗并阻止超额后的后续派发。未知费用不作为零成本，也不声称已实现费用硬限额。

用户投入按实际输入和确认次数记录；首次成功时间从任务发送到交付回执计时；任务质量核对约定业务与回归；总成本同时报告可获得的请求、Token、耗时和未知项。没有相同条件的对照时，不给出节约比例。

## 任务入口与确认信息

首页以业务目标组织构建、评测和改进优化；三种任务分别保存文字草稿，不提供智能体、版本或运行记录下拉框。助手从描述中定位目标，先查询已有对象、测试和证据，对仍不明确的目标集中澄清，固定来源后再确认执行范围。输入框从单行开始，随内容和窗口宽度调整高度。巡检体验使用已安装的工具和固定业务 Case，优先选择可用的启用版本，其他来源按需展开。没有样例时提供具体准备入口，不展示虚构运行结果。

任务预览说明具体动作、影响对象、交付内容和执行额度，完整来源、测试与技术内容折叠。工具权限与历史待办遵循 [DSH 原生权限合同](04_核心业务闭环与服务接口.md#management-assistant-capabilities)。普通查询与已完成回执默认显示具体操作和简短结果，完成或取消后离开输入区。

该结构采用 [NN/G 的确认对话框指南](https://www.nngroup.com/articles/confirmation-dialog/)中“明确动作及其后果、具体按钮、按需展开”的做法，以及 [GOV.UK 的确认信息设计](https://design-system.service.gov.uk/patterns/check-answers/)中“只展示相关信息、内容分组、按钮说明提交动作”的做法。共同表达原则当前在 [`user-facing-output` Skill](https://github.com/wr5912/harness-engineering-platform-data/blob/main/.agents/skills/user-facing-output/SKILL.md)维护，可由其他业务 Harness 按其实际装载方式复用；技能保持简短，不新增评分器或确认流程。

## 实际结果

| 路径 | 实际结果 | 适用范围 |
| --- | --- | --- |
| 首页巡检体验 | 从真实首页开始，助手自主派生版本、评测、启动独立实例和执行新 Session；五台设备的 Markdown、CSV 通过真实页面下载，内容与工具回执一致 | 基础 Mock 台账；没有检测真实设备 |
| 新建任务型智能体 | 真正创建独立 Agent，复用已有工具并绑定新 Preset；正常分页、漏页边界及身份/范围回归共 4 项通过，最终实例与报告核验通过 | 首次方案因重定义平台基础 Case 而不能执行；共享校验现于确认前拒绝该方案，失败记录保留 |
| 从业务失败改进 | 原始版本实测缺工具；独立派生后装配能力，修复 1 轮，最终 3 个冻结 Case 通过；暂停后的 Run 取消，重启恢复时额度与身份不变 | 最终实例探针已取得报告，但观测调用超过确认额度，任务保持预算耗尽，未标为成功交付 |
| 人工回退 | 在实际任务卡回退本任务的编辑和装配，恢复固定内容及模式、删除新增插件和空目录；完整文件内容及目录与父版一致，用例和原 Run 不变 | 原实例先停止，回退不声明其已重载；任务仍为额度耗尽，历史成功 Run 不代表回退后 Candidate 可交付 |
| 多步骤研究 | 固定资料生成包含横向比较、逐来源依据与许可限制的报告，独立核对真实下载的 11824 字节及摘要 | 不验证资料实时性、上游平台效果或普遍研究质量 |
| 自主训练 | 标准实例实际执行资源预检，明确缺少训练依赖并停止，没有生成训练指标 | 真实训练、候选比较及训练收益待具备算力和数据后验证 |

首页体验无需补充文字输入，一次整体确认，从开始体验到交付约 498 秒；完整会话及业务评测、最终实例探针共 36 次模型调用。首版 Task 快照记录 35 次执行调用，最后一次说明回复在完整会话中另行核对；当前计量已覆盖该收尾调用，并在用户发送新消息时结束旧任务归属。

新建智能体第二次验收约 358 秒，1 次需求输入、1 次整体确认，49 次模型调用，含目标、评审与实例探针；没有人工代装配资产。从首次尝试到第一次成功约 1596 秒，包含失败后的代码修复与等待，共 2 次任务输入、2 次确认、75 次调用。失败改进任务记录至少 62 次调用，超过其 60 次额度；其中被取消 Run 的统计不完整，不能把下界当作精确总额。上述费用均未知，不以调用次数推算账单，也不提供没有对照实验支持的节省比例。

程序确定性验证覆盖平台类型检查和构建、348 项插件测试、180 项 Python 适配层测试、95 项仓库测试，以及 32 项适配层 Node 的轨迹、取消、交付和来源比较测试。树摘要测试使用独立临时样本，不依赖已拆出的业务目录。仓库校验明确指定实际数据工作区，结果零错误、零警告。实机结果与这些机器合同分别记录，不互相代替。

精选页面、确认、回执、实际下载及回退记录见[程序界面证据](../../platform/plugin/test/evidence/task-delivery-20261016/README.md)。原始失败、取消及其后的成功分别保存，不改写真实运行结果；每份证据明确其验证范围。
