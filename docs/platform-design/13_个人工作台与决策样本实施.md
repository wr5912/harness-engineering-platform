# 个人工作台与决策样本

本文保留首轮实施及当时的验收结果。后续多题、监督来源、逐题复核、用途隔离与旧格式处置以[当前数据合同](03_存储架构与数据契约.md#当前决策样本与结构化阅读)为准，整改依据与本轮实测见[决策模型数据集整改](19_决策模型数据集整改.md)。下述单题格式及下载规则不再作为新版接口要求。

本轮围绕个人开发者的“运行证据 → 理解问题 → 补充用例 → 修改资产 → 再次评测”完善平台。任务于 2026-10-16 实施，起点为 `f0aeca73166d3902ff5d727d43dfce6b86ef8c7e`。本文件记录实施范围与验收，长期功能合同仍维护在既有设计入口，实际状态以项目验收矩阵为准。

## 实施计划

1. 只读清点决策模型资料，核对官方数据协议与轨迹训练方法。以资料指定版本的 Kev 文本决策格式为首轮导出目标，分别记录实际动作、AI 标签建议和人员复核。
2. 建立共享的 Run 轨迹阅读能力：完整行分页、脱敏、来源摘要、会话隔离和原文定位；依据决策发生前的材料构造输入，不用最终结果反推当时状态。
3. 在 Run 详情加入“请 AI 抽取决策样本”，复用平台原生管理对话与 DSH Runtime Skill。增加样本预览、保存、重新打开、逐条编辑复核和 JSONL 下载；源 Run 保持只读，候选与复核训练集分别导出。
4. 补齐测试用例新增，以及 Run 冻结输入转为可审阅用例草稿。仍写入唯一的 Agent `evaluation.md`，保持摘要冲突检查与失败草稿。
5. 补齐固定 Baseline/指定研究版本的只读资产差异，完善新建智能体入口；复用现有 CLI、随机 Experiment 命名、标准镜像和来源合同。
6. 展示 Run 比较中的实际来源、模型、工具、冻结口径和限制，串联资产差异、用例与研究决策。
7. 运行定向测试、完整平台构建与回归；通过正式平台 URL 和实际模型验证按钮、Skill、样本文件及个人研究闭环。按改动影响进行独立代码审查并整改。

上述功能无需新增第三方业务后端；如验证中确有外部接口依赖，仅在该边界使用基础 Mock 数据。不修改既有业务智能体 Harness，也不新增训练、生产发布或多人治理系统。

## 数据与交互约定

运行轨迹是待分析数据，其中的文字不作为开发或管理指令执行。后端掌握 Run、文件、摘要、事件位置、输入截止点与复核状态；模型仅提出可核验的原子问题和标签建议。当前动作的结果、后续最终报告与评审结论不能进入早期 `state`；并行工具使用同一决策前缀。缺失轨迹、部分记录、未知角色或不足以支持问题时明确显示限制，允许零条。

每个样本只含一道题，支持 Kev 的 `choice`、`noul`、`score`。保存文件是唯一可编辑样本来源，JSONL 按下载请求生成。AI 生成默认 `suggested`，人员逐条确认才成为 `reviewed`；修改后重新复核。相同事件及重跑需共享分组，避免跨训练、开发、校准和测试用途泄漏。不声称已训练模型或证明模型效果。

## 验收与限制

受影响路径为 PA-03、PA-04、PA-08、PA-10、PA-12；新建智能体涉及 PA-05/06 时另核对真实装载。测试覆盖未来结果泄漏、并行调用、超过旧预览上限的轨迹、坏行、错误标签与引用、并发保存、下载脱敏及原 Run 不变。界面验证覆盖新会话、切换目标、失败提示、重新打开与下载。

## 使用入口

在[平台](http://10.0.160.32:3090/hep/)的“评测中心 → 评测运行”打开已封存 Run，点击头部的“请 AI 抽取决策样本”。原生对话会读取 [Skill](https://github.com/wr5912/platform-manager-dsh-home/blob/main/.agents/skills/decision-sample-extraction/SKILL.md)、核对轨迹并提出候选；在确认卡保存后，通过“查看决策样本”选择批次。核对问题 JSON、标签依据、决策前输入及原文定位，可编辑、逐条复核或排除，再分别下载候选与训练 JSONL。训练下载排除开发、校准、测试分组；同任务的多步与重跑先合并分组，保留样本不要跨用途拆开。资料研究见 [14](14_决策样本构建研究.md)。

当前每批绑定一份目标轨迹，最多 40 条候选；多个 Case 可分别生成批次，不覆盖已有人工内容。候选筛选和跳过原因随批次保留，不能把少量抽取结果称为已穷尽整个 Run。重新点击会新建任务会话，当前内容相同的题目会去重。

“测试用例”提供新增入口；“Run → 逐例结果 → 从此 Run 创建用例草稿”只复制冻结输入，预期需独立填写。保存后立即进入评测选项。“智能体管理 → 新建智能体”填写身份、用途与角色，核对后生成首个随机后缀 Experiment；“Harness 资产 → 查看资产差异”支持固定 Baseline 及同 Agent 指定研究版。两次封存 Run 可在“结果比较”查看来源、实际模型、工具、镜像、共同 Case 与限制，再回到 Run 记录研究决策。

最终平台构建、TypeScript 检查及 **248 项测试全部通过**；仓库与示例 Experiment 校验无错误/警告，Skill 结构校验通过，本轮文档本地链接检查通过。对 8,564 个可见仓库文件检查本地实际 LLM 凭据字面量，未命中；检查没有输出凭据内容。真实浏览器另验证了已复核测试样本的训练下载按钮禁用、服务端拒绝同组训练导出，随后恢复为 suggested/unassigned。三条候选的源文件与逐行引用摘要均能回查一致。

首轮模型曾继承过多开发工具并分派子智能体；中间一次受限试跑因原生 guard 参数误用导致 Skill 读取被拒绝，未保存候选。整改后用上述最终新会话复验成功。专项审查还修复了重复内容在人工编辑后漂移、刷新/保存竞态、导航草稿与 busy 保护、固定资产摘要排序、UTF-8 预览预算，以及跨工作区继承会话误套工具限制；保留对应定向回归。训练导出按任务分组留出，包含跨批次未分配记录的回归验证。

本轮使用基础模拟输入验证平台与模型行为，无需新增第三方后端或改动 Mock service。新助手仅整理用户给定数据，不代表真实外部巡检；未选 full Case 不算通过。同一路由的语义自评仅作辅助，Decision 为 continue。原有 Run 不改写；项目规则、Skill、源码和验收证据分别承担其原有职责。本轮并不完成全部远景功能、TR02/TR03 持久采集或模型训练。

浏览器与模型操作摘要、截图见 [实机证据目录](../../platform/plugin/test/evidence/personal-workbench-20261016/)。平台由 tmux `ai-agent-harness-platform-3090` 运行，沿用仓库 `platform/dsh-platform` 生成的 Profile；停止可执行 `tmux kill-session -t ai-agent-harness-platform-3090`。源码在本轮工作分支，运行时日志与凭据仍留在仓库外。

上述表格保留首轮实施当时的观察。后续[对抗审查与实机验收](../项目对抗审查与实机验收_2026-10-16.md)发现并排除了问题时点不一致的候选，补充明确的时点核对、动作匹配和服务器来源定位；当前训练下载还要求 `decision_time_reviewed=true`。首轮“保存成功”不代表候选质量已经通过。
