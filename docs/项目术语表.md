# 项目术语表

本表用于对齐人与 AI 的用词。优先使用表中的中文名称，首次出现时可附英文；代码标识符、协议字段、命令、路径、稳定 ID 和外部产品名保持原文。评估是判断过程，评测是执行测试及取得数据的过程，二者按语境使用。

“当前”表示平台开发与 Harness 研究中使用的概念，不保证其所有操作均已实现；实现与验收状态见[项目验收矩阵](ai-agent-harness项目验收矩阵.md)。“设计”表示待实现方案；“历史参考”只解释原材料，不引入当前义务。详细合同由各节所列来源维护，本表只维护词义和歧义边界。

| 首选名称 | 英文或标识 | 含义与歧义边界 | 适用 |
|---|---|---|---|
| 研究模式 | Research Mode | 用可复现实验判断业务 Harness 变化价值的研究方法；平台功能开发按实际需求和项目路径验证 | 当前研究流程 |
| Harness 工程平台 | Harness Engineering Platform、HEP | 当前持续建设的项目，以平台需求为主线，将验证有效的研究成果融入功能；能力状态以实际实现和验收证据为准 | 当前／设计 |
| 开发智能体 | 开发 AI、Codex | 修改仓库的 AI；读取业务角色指令不代表切换业务身份 | 当前 |
| 开发工具 Harness | `.codex/`、根级 `AGENTS.md`、`.agents/skills/` | 组织研发的指令、工具与流程；不同于容器内业务 Harness | 当前 |
| 业务智能体 | Agent | 执行业务任务的对象；Agent ID 标识其身份，实例和版本另行标识 | 当前 |
| 评审／归因 Harness | judge / attribution | 在评估中判断输出或分析原因的专用运行配置；不是开发技能，也不是被测业务角色 | 当前 |
| 项目技能 | `.agents/skills/` | 按工作区归属维护的技能：程序仓库供研发使用，数据仓库供管理助手处理业务；“已读取技能”不证明目标实例已装载业务能力 | 当前 |
| 单一事实源 | Single Source of Truth、SSOT | 同一当前事实的一处可编辑来源；引用、不可编辑派生视图和历史快照具有不同职责 | 当前 |
| 受控副本 | controlled copy | 来源与摘要受记录的本地规范；本地修订版须区分输入原版与当前摘要 | 当前 |
| 本地术语修订版 | local terminology revision | 在原位置统一术语的已标明版本；不声称与输入原件逐字节相同，不自动改变规范适用范围 | 当前 |
| 原始导入 | `evolution/history/imports/`、设计 sources | 迁移或设计的输入来源；清洗、本地修订与运行证据须分别识别 | 当前／历史参考 |
| 草案 | draft | 尚未生效的建议；归档草案中的“必须”不成为当前规则 | 历史参考／设计 |
| 项目 Memory | Memory | 仓库外的开发辅助上下文；不是规范、资产或评估结果事实源 | 当前 |
| AI 纠错记录 | `AI纠错记录/YYYY-MM-DD.jsonl` | 用户明确纠错的追加记录；历史要求须结合当前有效指令解释 | 当前 |
| 项目验证路径 | `PA-01` 至 `PA-12` | 独立可成败的项目工作链；不是业务 Case，也不是生产门禁 | 当前 |

## Harness 研究与资产演进

本节依据[研究演进](../AGENTS.md#研究演进)、[harness-evolution](https://github.com/wr5912/harness-engineering-platform-data/blob/main/.agents/skills/harness-evolution/SKILL.md)及[Experiment 合同](https://github.com/wr5912/harness-engineering-platform-data/blob/main/.agents/skills/research-eval/references/experiment-contract.md)。

| 首选名称 | 英文或标识 | 含义与歧义边界 | 适用 |
|---|---|---|---|
| Harness | Harness | 影响 Agent 行为的提示词、Preset、Skill、Plugin、工具和配置资产组合；不包含整套 Runtime HOME | 当前 |
| 基线引用 | Baseline | `git:<commit>`、`release:<id>` 或 `none:first-experiment`；用于比较的固定来源，不复制可编辑 Baseline 目录 | 当前 |
| 实验 | Experiment、`EXP-<agent-id>-NNN-r…` | 一次有目标、变化、比较和决策的研究单元；编号表示创建顺序，不表示继承关系；既有短编号保留 | 当前 |
| 待比较工作树 | Candidate、`candidate/` | Experiment 内可编辑的 Harness 资产；“候选版本”在当前语境指它，不代表生产发布准入 | 当前 |
| 主线版本 | mainline | 当前研究中作为继承基础的完整版本；须说明固定来源，不能用“编号最大”替代来源判断 | 当前 |
| 并行能力融合 | fusion | 将已确认需保留的不同来源能力组合到独立 Candidate，并检查组合装载与行为 | 当前 |
| 变体 | Variant | 同一智能体因目标或算力等差异形成的 Harness 版本；不等于新增 Agent 身份 | 当前 |
| 终端变体 | `end` | 已固定完整可恢复父版、证明任务效果等效及资源差异的终端版本；后续主线无需继承其差异 | 当前 |
| 评估 | Evaluation | 按研究假设判断变化、回归和限制的过程；范围由问题决定，不设通用固定 Case 数 | 当前 |
| 研究运行 | Run、`run-<UUIDv4>` | 保存实际来源、环境、输入、观察与限制的一次研究执行记录；不等于 Session、容器或后台任务 | 当前 |
| 研究决策 | Decision | `adopt` 采用、`continue` 继续、`reject` 否决、`inconclusive` 无法判定；不同于执行状态或 Case 判分 | 当前 |
| 决策样本 | decision sample | 一份模型可见状态及其命名决策问题、监督目标和来源；不同于 Experiment 的研究决策，也不等于完整执行轨迹 | 当前 |
| 监督目标与标签来源 | target / label provenance | 题目的待学习或待评测输出，以及它来自实际动作、模型建议或人员标注的事实；人员复核不会把模型来源改写成人工原始标注 | 当前 |
| 分布标签 | probabilistic target | 在明确候选或有序等级上的概率分布；结构合法不代表经过校准，教师输出也不自动等于人工真值 | 当前 |
| 样本用途与留出 | split / held-out | 训练、开发、校准、测试或未分配用途；未分配不自动用于训练，已知同源任务保持一致的留出边界 | 当前 |
| 研究版本 | Research Release | 自包含、不可变、可校验、值得保留的研究版本；不表示生产可用或业务启用 | 当前合同；复现能力见 PA-11 |
| Git 提交 | commit | 固定源码树的版本身份；dirty 状态另行记录，分支名本身不固定内容 | 当前 |
| Git 标签 | tag | Git 对象的辅助名称；附注标签对象和解引用提交不同，不自动等于 Research Release | 当前 |
| 继承来源 | parent / source | 当前目标实际采用的固定版本与并行能力来源；与 Baseline 的比较用途分别说明 | 当前 |
| 资产回流 | source writeback | 将开发中产生的有效 Harness 资产保存到当前 Candidate；不复制 Session、缓存或整个 HOME | 当前 |

## DSH 运行、装载与接入

本节依据[开发与评测启动器](DSH开发与评测启动器设计方案.md)、[容器启动器](DSH容器开发启动器设计方案.md)、[来源解析](../runtime/adapters/dsh-container/source_contract.py)及[当前平台接入合同](platform-design/02_系统架构与部署设计.md#当前最小平台接入合同)。

| 首选名称 | 英文或标识 | 含义与歧义边界 | 适用 |
|---|---|---|---|
| DSH 运行时 | DSH Runtime | 装载并执行 Harness 的外部运行框架；源码不混入本仓库 | 当前 |
| Runtime 来源锁 | `runtime/adapters/dsh-container/source.lock.json` | 全仓 DSH 来源版本的唯一可编辑声明；Candidate 不另维护版本锁 | 当前 |
| 标准镜像 | image | 同一业务智能体新实例共用的标准 Runtime 镜像；易变 Harness 资产通过挂载装载 | 当前 |
| 镜像标签／摘要 | tag / digest | 标签是名称，摘要用于固定镜像内容；不能仅凭同名标签推断镜像一致 | 当前 |
| 构建指纹 | `image_build_fingerprint` | 校验标准镜像与锁定来源及构建输入是否相符的标识；不同于镜像标签 | 当前 |
| 实例 | instance | 带固定来源、HOME、配置和生命周期的运行单位；实例名称、主容器与 Compose 项目须明确关联 | 当前 |
| 容器 | container | 承载一个实例进程的隔离运行对象；容器启动不证明模型或业务工具可用 | 当前 |
| Runtime HOME | `$DSH_HOME` | Session、设置等运行状态所在目录；不作为完整 Harness 资产入仓 | 当前 |
| 工作区 | workspace | Session 可见的工作目录；开发工作区、目标业务工作区与归因只读 Run 目录分别指明 | 当前 |
| 挂载 | bind mount / volume | 将宿主资产或运行目录提供给实例；需核对实际源、目标和只读属性 | 当前 |
| 配置组合 | Profile | DSH 启动时采用的插件与配置组合；不是 Agent 身份或一个 Session | 当前 |
| 预设 | Preset | DSH 可装载的角色与能力配置；业务、评审、归因 Preset 按实际角色区分 | 当前 |
| 运行时技能 | Skill | 供智能体运行时使用的技能资产；管理助手技能位于数据仓库 `.agents/skills/`，业务智能体技能由其 Candidate 装载，均与程序仓库研发技能分开 | 当前 |
| 插件 | Plugin | 通过 DSH 扩展机制装载的功能包；源码存在、构建成功与实际激活分别核验 | 当前 |
| Cordis | Cordis | DSH 使用的插件与依赖装配机制；保留产品名 | 当前 |
| MCP | Model Context Protocol | 模型工具接入协议；服务发现、授权、工具目录和真实调用是不同检查步骤 | 当前 |
| OpenAPI 规范地址 | OpenAPI spec URL | 描述外部 HTTP API 的规范入口；不同于 MCP 传输地址，不能互填 | 当前 |
| MCP 服务器 | MCP server | 向 DSH 提供工具的连接对象，可由 OpenAPI 规范适配生成 | 当前 |
| 工具回执 | tool receipt | 本次实际工具调用返回的事实及状态；不同于提示词示例、工具目录或合成预置值 | 当前 |
| 工具行为约束 | Guard | 目标 Harness 中限制工具或动作的配置与实现；不是所有 Experiment 必须新增的仓库治理设施 | 当前相关 Candidate |
| 业务网关 | business gateway | 统一承接业务用户到业务智能体的入站访问；采用 DSH 插件服务，与平台管理认证、出站 MCP 管理分别负责 | 已选设计 |
| 开放资格 | agent exposure | 某 Agent 是否允许纳入业务网关；与人到 Agent 的授权分别判断，不等于实例启动、版本发布或 Research Release | 已选设计 |
| 身份认证 | authentication | 验证当前凭据并输出经验证的身份声明；不直接授予业务访问权限 | 已选插件分类 |
| 身份信任 | identity trust | 接受可信来源、建立稳定主体映射并检查有效状态；与认证、业务授权分别表达 | 已选插件分类 |
| 风险评估 | risk assessment | 运行时对指定对象或动作形成有范围和时效的风险事实；不是 Harness 效果 Evaluation，不自行授予权限 | 已选插件分类 |
| 访问授权 | access authorization | 综合主体、动作、资源、归属及必要风险事实，给出允许或拒绝；实际阻断由执行点落实 | 已选插件分类 |
| 访问执行 | access enforcement | 网关、Runtime、工具及组合叶子在真实边界落实授权结果；不是第五套身份或策略来源 | 已选设计 |
| 生效回执 | enforcement acknowledgement | 运行端确认已应用某限制版本的观察；与配置保存、页面刷新和目录更新分别表达 | 已选设计 |
| 非 owner 调用方 | non-owner Peer | DSH 原生可受资源授权约束的调用身份；默认 owner 连接不能充当业务多用户隔离 | 原生接缝／设计 |
| LLM API Key | LLM API Key | 模型服务凭据，仅保存于本地忽略的 `*.llm-api-key` 文件；与专用实例密码的 Git 边界不同 | 当前 |
| 会话 | Session | DSH 的连续上下文与事件容器；一次 Run 可使用多个独立 Session | 当前 |
| 轮次 | Turn | Session 内的一轮交互；不等于工具调用或完整研究运行 | 当前 |
| 模型调用 | Call | 一次模型调用；可见正文、推理和工具事件按实际协议区分 | 当前 |
| 模型词元／认证令牌 | token / Token | 模型用量中的 token 是计量单位，认证 Token 是凭据；交流时明确用途，认证令牌不进入普通日志与证据 | 当前 |
| 执行轨迹 | Trace | 关联模型与工具执行的事件证据；页面可见不等于已完整持久保存 | 当前 |
| 轨迹片段 | Span | Trace 中的一个可关联执行片段；具体字段以实际采集方为准 | 当前 |
| 只读评测模式 | `--mode eval`、eval-only | 宿主维护资产、实例只读装载被测 Harness 的当前容器模式 | 当前 |
| 容器内开发模式 | authoring | 历史开发路径；历史证据不代表当前入口仍支持此模式 | 历史参考 |
| 非交互终端 | non-interactive | 无交互输入的执行环境；需按命令合同提供 `--non-interactive` 等必要参数 | 当前 |

## 测试、证据与结论

本节依据[验收矩阵](ai-agent-harness项目验收矩阵.md)、[research-eval](https://github.com/wr5912/harness-engineering-platform-data/blob/main/.agents/skills/research-eval/SKILL.md)和[业务评估定义](https://github.com/wr5912/harness-engineering-platform-data/blob/9afc8fd0047367deb9df5b51595f101835359044/agents/security-operations-expert/evaluation.md)。

| 首选名称 | 英文或标识 | 含义与歧义边界 | 适用 |
|---|---|---|---|
| 用例 | Case、`U-…` | 一个输入及可观察的预期行为；稳定 ID 不因文字统一而改名 | 当前 |
| 需求／验收条件 | `REQ-…` / `AC-…` | 某项需求或其完成判断的标识；不是每个 Experiment 必须创建的材料 | 当前可选／历史参考 |
| 评估集 | Eval Set | 当前比较选用的输入与判断口径；人工定义和机器消费者以一个当前来源连接 | 当前 |
| 单次试验 | Trial | 外部规范或历史评估中的一次重复执行单位；当前 Run 不强制增加此层对象 | 历史参考 |
| 预期行为 | expected behavior | 输入应触发的可观察结果；动态数量、链接等须由本次工具事实支持 | 当前 |
| 机器结果／复核结论／有效判定 | verdict / review / effective result | 自动记录、人工复核与最终采用判断分开表达；合并展示不合并字段语义 | 当前 |
| 快速／完整评测 | fast / full | 执行器选择的评测范围或模式；默认值以当前 CLI 为准，与业务模型配置分开 | 当前 |
| API 语义评测 | DSH Runtime API | 经运行时 API 执行 Case 并判断业务行为；不能由 HTTP 可达性代替 | 当前 |
| UI 冒烟 | browser UI smoke | 检查页面入口、会话与关键交互；浏览器定位失败不能直接判为业务能力失败 | 当前 |
| 静态合同检查 | validation | 文件、类型、摘要等确定性检查；不证明模型行为或研究假设成立 | 当前 |
| 装载验证 | load verification | 证明实际实例采用了目标源码、配置与依赖；不同于构建成功 | 当前 |
| 对照比较 | baseline comparison | 在说明来源、输入与环境差异的前提下比较 Run；工具支持比较不代表已执行真实对照 | 当前 |
| 可比性 | `compare.comparable` | 已记录条件的一致性判断；不自动证明业务等效或因果改善 | 当前 |
| 封存 | finalize / sealed | 固定完成的 Run 原始事实；补充或更正另存证据，不静默覆盖 | 当前 |
| 缺口 | gap | 当前目标所需且尚缺的事实或能力；不把未来清单自动当作当前缺陷 | 当前 |
| 不可判定 | inconclusive | 证据不足以判断假设或效果；与命令执行失败、业务结果失败分开 | 当前 |
| 项目与工具链验证 | project verification | 判断开发规则、CLI 和 DSH 接入按合同工作 | 当前 |
| 研究版本复现 | Research Release reproduction | 按版本清单恢复、校验并重新装载；目录合同通过不等于启动器支持 release 来源 | 当前合同 |
| 业务验收／生产部署验收 | business / production acceptance | 分别判断业务目标和生产交付；不能从静态检查、HTTP 200 或单个成功回复推断 | 依任务授权；生产不属当前模式 |

## 平台设计对象

本节术语来自[数据契约](platform-design/03_存储架构与数据契约.md)、[业务闭环](platform-design/04_核心业务闭环与服务接口.md)和[实施路线](platform-design/05_实施路线与迭代计划.md)。各词的当前或设计语境见适用列；当前平台能力以 PA-12 核验。

| 首选名称 | 英文或标识 | 含义与歧义边界 | 适用 |
|---|---|---|---|
| 全局 DSH 平台 | `platform/` | 通过系统全局 DSH 装载的管理界面与工具；不同于容器内业务 Agent | 当前 |
| 平台管理助手 | Platform Management Assistant | 平台内通过管理对话和管理工具，协助用户管理智能体资产、评测、实例及工具接入的 AI。保持管理身份，区分平台程序与当前数据工作区；读取业务 Harness 不代表切换为业务智能体，也不等同于修改平台源码的开发智能体 | 当前；能力范围以实现与验收证据为准 |
| 命令行界面 | CLI | 以命令和参数访问工具能力的入口；命令成功所证明的范围取决于实际检查内容 | 当前 |
| 图形用户界面 | GUI | 页面和控件组成的操作入口；界面展示与底层业务能力分别核验 | 当前／设计 |
| 语言用户界面 | LUI | 以自然语言表达管理意图的交互入口；不意味着可绕过确定性服务直接执行副作用 | 设计 |
| 管理 Harness | Meta-Harness | 支撑平台管理助手的角色指令、Skill、工具、配置与上下文规则，组织目标定位、执行和结果核对；业务原则和 Skill 由数据仓库维护，程序负责工具和装载合同；不同于业务 Harness、开发工具 Harness 或单次管理会话 | 当前／设计 |

| 资产来源摘要 | `source_digest` | 标识实际声明装载的资产内容；不同于镜像摘要，也不能单独证明运行实例已装载该内容 | 设计 |

| 会话绑定 | Session Binding | 会话与目标实例等对象的明确关联 | 设计 |
| 执行调用 | Invocation | 平台层的一次执行关联；不等于底层模型 Call 或研究 Run | 设计 |
| 管理操作 | Operation | 有请求身份、状态和回执的管理动作；未知结果需核实，不自动重复副作用 | 设计 |
| 类型化工具 | Typed Tool | 以明确的输入输出结构调用确定性服务的工具入口；结构校验通过不代表动作已获授权或执行成功 | 设计 |
| 请求键 | `request_key` | 关联同一管理请求的身份；具体幂等与恢复合同由数据契约维护 | 设计 |
| 用例提案 | CaseProposal | 改进过程产生的候选用例；不直接改写正在执行的评估口径 | 设计 |
| Harness 版本 | HarnessVersion | 未来平台的版本对象，可有 `published`、`withdrawn` 状态；不同于当前 Research Release | 设计 |
| 业务启用绑定 | Deployment | 为新业务会话选择版本的启用事实；不同于启动容器或保存研究版本，旧会话不随之静默换版 | 设计 |
| 发布／撤回／启用 | published / withdrawn / enable | 分别是版本状态与业务使用动作；不与 Git 推送、打 Tag 或研究决策互换 | 设计 |
| 能力 Hub | capability hub | 平台设计中的能力发现与接入页面；保留名称中的 Hub，不泛指任意 MCP 目录 | 设计 |
| 非模型路径优先方案 | no-compute | [算力变体草图](platform-design/06_界面与前后端渐进建设.md)中的方案标签，表示优先采用规则、缓存等替代模型生成；不表示零计算或必然没有模型调用，资源用量须实际测量 | 设计草图 |
| 阶段 | R0–R5 | 平台路线中的条件阶段；与外部规范的 R1/R2/R3 发布分级不是同一体系 | 设计 |

| 概念验证 | POC | 针对明确技术假设的有限验证；通过后也不自动授权建设完整平台 | 设计／当前任务可用 |
| 工作切片 | Backlog slice | 围绕一个完成条件的最小实施范围；任务列表存在不表示已获实施授权 | 设计 |
| PostgreSQL | PG | 未来有真实事务需求时可选的存储技术；当前研究闭环不以数据库为前提 | 设计 |

## 交流时的最小限定

| 容易歧义的表达 | 清楚的表达方式 |
|---|---|
| “最新版” | 指明 Agent ID、Experiment 或 Git 提交，并说明要比较的基线或继承来源；不要仅凭编号选择 |
| “本地入口” | 指明工作树、目标主机、实例和端口；确认实际进程后再提供地址，认证信息单独处理 |
| “验证通过” | 说明对象、层级与证据，例如“规范摘要检查通过”“新 Session 完成三个巡检 Case”；给出未覆盖层面 |
| “发布” | 指明要执行 Git 推送、打 Tag、保存 Research Release，还是未来平台版本发布／业务启用；按实际授权操作 |
| “运行／调用” | 指明研究 Run、DSH Session、Turn、模型 Call、工具调用或平台 Invocation |
| “基线／候选” | 在当前研究中使用 Baseline 引用和 Candidate；引用外部历史生产语义时注明来源语境 |

## 全仓用词边界

正文、界面标签、注释、模板、生成文本与相关断言按同一词义维护。评估／评测、Agent／智能体、Runtime／运行时等允许在定义清楚后按语境使用，不做无差别字符串替换。`runId` 等第三方字段、命令和路径保持原名，解释时说明所属对象。

受控规范、原始导入和归档草案在原位置标明本地术语修订身份；它们描述的历史架构、生产流程和未生效建议仍保持原有适用范围。原版摘要与 Git 定位保留在各来源入口。纠错原始记录、封存 Run、Research Release 和原始运行证据保留当时用词，不能用本表回写历史事实。
