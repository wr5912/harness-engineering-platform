# DSH 平台开发

任务分类与分支选择遵循[根级分支与开发工作流](../../../AGENTS.md#分支与开发工作流)。本技能用于按实际需求建设平台和通用工具；已有可靠路径时直接实现，技术或效果不确定时先做必要研究或 POC，并在受影响路径验证后纳入功能。设计输入本身不构成具体任务的实施授权。

## 确定范围

- 阅读根级 `AGENTS.md`、`docs/standards/SOURCES.md`、`docs/standards/PROJECT-INTERPRETATION.md` 和[项目验收矩阵](../../../docs/ai-agent-harness项目验收矩阵.md)，确定受影响的 `PA-xx` 与可观察的完成条件。
- 核对目标入口、调用方、配置、构建与现有测试，检查 Git 工作树并保留已有改动。平台任务从[平台设计维护入口](../../../docs/platform-design/README.md)定位对应设计；涉及装载时读取[当前最小平台接入合同](../../../docs/platform-design/02_系统架构与部署设计.md#当前最小平台接入合同)。以当前源码和实际装载核实能力，不把计划当作实现。
- 涉及运行环境时先核对目标主机、工作树、实例、进程／端口与实际来源；按根级入口检索相关经验与术语。
- 需求足够明确时直接形成最小修改范围并实施，已有授权不重复确认；只有会改变目标或完成条件的缺失信息才需要澄清。

## 实施与接入

管理助手相关变更必须遵守根级“DSH 原生对话与 Harness 完整复用”硬性原则：嵌入会话使用原生默认视图，不替换工具回执或输入区，不用 CSS 隐藏原生对话控件，不安装额外的模型流处理、重试、会话资格检查、可选资产预检、提示词装配注入、describe 解锁或动态工具 Schema 过滤。仅绑定 manager-workspace 并撤销其他原生工作区登记；业务写入校验与回执处理保持在共享服务中。状态文字“思考中”的既有调整保留，核对对应适配器测试。

优先复用 DSH 和本仓库已有能力。按根级工程语言取向维护源码与构建制品，检查同一变化直接影响的调用方、配置与消费者。

涉及打包、部署、增量更新或安装目录迁移时，遵守[根级“打包部署更新必须经过工具”原则](../../../AGENTS.md#项目定位与工作方式)，使用 `platform/dsh-deploy`；缺少能力或执行失败时，先整改并验证工具，再通过工具继续任务。

涉及 MCP 组合编排资产开发时，通过管理助手 HOME 的 [mcp-composition 公开入口](https://github.com/wr5912/platform-manager-dsh-home/blob/main/.agents/skills/mcp-composition/SKILL.md)交接业务目标、允许范围及当前编排身份，由其返回资产变更与分层验证回执。通用执行器、装载或接口缺口由研发处理，再回到管理助手复验；未知回执先查询原结果，不重放调用。接口、组件及执行事实以源码和实际回执为准，不读取业务 Skill 的私有方法或另存一套。

全局 DSH 平台的启动入口、Profile 与插件集中在 `platform/`；容器内业务 Agent 的 Harness 仍由对应 Experiment 的 Candidate 装载。修改平台接入时核对这两条来源链，避免把开发身份、平台 Profile 和业务 Preset 混用。

平台页面、启动器和通用工具按项目路径验证，不为普通平台修改建立业务 Experiment；技术研究依据按需保存在既有任务或设计记录中。若同时改变业务 Harness 语义，对该部分使用管理助手 HOME 的 [`workspace-management`](https://github.com/wr5912/platform-manager-dsh-home/blob/main/.agents/skills/workspace-management/SKILL.md)，分别保留功能验证与研究比较的结论。仅编写页面开发任务清单时改用 [`dsh-platform-task-list`](../dsh-platform-task-list/SKILL.md)。

## 验证与交付

运行受影响的现有确定性检查与测试。涉及 DSH 插件构建或装载时，核对构建产物和实际加载来源，按根级“变更生效优先免重启”原则验证；涉及界面变更时按[根级界面交付质量](../../../AGENTS.md#界面交付质量)检查相应浏览器路径，并核对直接受影响的既有交互、创建、编辑、类型切换、保存回读和失败路径；具体覆盖由本次变化决定。静态规则或文档变更按其实际影响验证，不为此启动业务实例或创建 Run。

完成前按[项目审查原则](../../../docs/项目审查原则.md)检查本次差异、链接、配置与敏感信息。将项目验证结果和缺口更新到验收矩阵对应路径，研究事实留在实际涉及的 Experiment 中。报告已验证内容、未验证内容与适用边界；是否提交、推送或发布仍按根级授权规则执行。

导出或安装验收结束时，按[验收环境收尾](../../../docs/platform-design/23_离线一键打包与安装.md#验收环境收尾)清理临时服务并核对端口；保留会话、Run 和失败证据不要求保留运行服务。仍需用户验收的入口明确列出用途及清理时点，不能把遗漏的服务默认为保留项。
