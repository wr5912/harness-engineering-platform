# 审查项目文档

范围与判断方法以[项目审查原则](../../../docs/项目审查原则.md#文档与数据)为准；写作规则以[根级文档约定](../../../AGENTS.md#文档与数据质量)为准。

1. 固定用户问题、目标版本和文档类型。区分当前可维护说明、机器消费合同、原始输入与冻结历史；由现有入口按需阅读，沿直接引用核对来源。
2. 选择一条真实读者任务，从入口追到详细步骤、当前实现及结果依据。检查必要输入、适用条件、失败去向和信息是否足够，不能只看篇幅或格式。
3. 核对同一事实的维护位置，检查链接、锚点、图件、上级入口与生成器。删除建议必须有失效或已完整迁移的证据；无引用、同名、时间久仅是线索。
4. 涉及解析文档的程序时，比较实际解析的全部字段与原文边界；核对编辑、选择执行和历史读取的共同合同，不能只数标题或 Case。
5. 按影响说明证据、建议与验证缺口；已有整改授权才修改。精简后仍需保留必要条件并复走受影响的读者路径。

不以本技能替代业务用例审查或 Skill 审查；分别交给数据侧 `evaluation-review` 或 [reviewing-agent-skills](../reviewing-agent-skills/SKILL.md)。
