## Steelman

明确工具序列降低了初次编写成本，也让执行步骤可理解。若 MCP 工具名称由统一团队长期承诺兼容、步骤需要动态判断，就可能合理。

## 发现 SK-001（P2，静态风险、待证实）

- **证据**：`sample/SKILL.md:20-27` 明确写死名称。
- **风险机制**：若工具名或服务名易变且没有兼容适配，更新后可能调用失败。
- **最小建议**：优先验证有无稳定接口/别名；没有时改写为能力依赖，运行时核对已发现工具。不要创建庞大的语义路由平台。
- **验收**：真实工具重命名与参数变更的兼容测试。

## 发现 SK-002（P2，待实验假设）

- **证据**：指令列出 5 步固定调用，但尚无实际 Trace。
- **假设**：若上述步骤在多数任务完全确定，可以下沉为单个同域复合 MCP 工具，减少 Agent 参与轮次。
- **验收**：保持任务集相同，在有无复合工具两种方案上测成功率、模型轮次、Token/成功任务、延迟。

## 结论

**保留 Skill，但优先验证兼容契约与固定编排收益。** 在没有失败轨迹前，不断言“必然失效”或“已降低 Token”。
