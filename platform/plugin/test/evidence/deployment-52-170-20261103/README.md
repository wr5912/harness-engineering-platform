## 工具缺陷与整改

| 暴露的问题 | 固化到工具的处理 |
|---|---|
| 170 无全局 Git | SSH 执行装载安装包的工具环境，使用随包 Node、Git。 |
| 完整数据 `cat-file` 超出子进程缓冲区、集中 JSON 超出 V8 字符串长度 | 按 64 MiB 读取对象；文件去重，逐记录压缩，使用二进制 SSH 传输。 |
| 目标 npm 不可达，跨架构依赖不能直接覆盖 | 只传缺少的纯 JS 依赖，保留 ARM64 原生依赖，核对锁文件与可执行入口。 |
| 旧安装源码或原生预检重建的制品与清单不同 | 源码必须精确匹配 Git；制品须由未改动源码和现场依赖逐字节复现后才修订清单。 |
| 历史管理技能修改、已停止跟踪的依赖文件发生冲突 | 只接受内容精确匹配来源历史的技能；备份原件；取消跟踪时不穿透现场依赖链接删除文件。其他冲突停止。 |
| 离线 prepare 仍触发 pnpm 隐式联网并破坏依赖目录 | 禁用 pnpm 脚本前自动安装；从工具自己的已核验备份恢复依赖并重建 `.bin`。加入受进程来源约束的 `--cancel-prepare` 恢复入口。 |
| 制品复核时构建 cwd 错误，入口被标记为 external | 使用对应适配器目录作为 cwd；回归夹具检查相对入口。 |
| 完整数据更新逐次过滤大清单过慢 | 使用按路径索引的清单更新。 |

首轮 52 已写入双仓更新，但后续构建核验失败；170 首轮更新后离线准备曾卡住，依赖恢复后又暴露相同构建 cwd 缺陷。修复后通过同一工具完成恢复和激活。保留本目录的原始失败日志；它们不代表最终状态。浏览器首次因原生新建会话没有文本按钮、第二次因 SPA 保留隐藏页面而定位超时，调整探针后通过；这两项是探针问题，未修改产品。
