## 配置合同与修复范围

DSH 原生 `@deepseek-ai/dsh-mcp-client` 负责连接、发现和工具装载；包内 MCP 服务端负责分组与固定组合。独立模式复用共用 MCP 管理器，不依赖平台统一网关。分组连接复用实际 DSH Web 服务地址，内部平台分组发现不占用外部发现队列，避免容器监听地址错误与嵌套发现互相等待。冻结资产保持只读，运行记录写入持久 HOME。按名称选择的挂载范围同时用于装载和后续请求目标核对，避免拿筛选后的连接与未筛选配置比较，导致原生客户端无法发现策略和故障诊断工具。新增真实原生客户端用例在修复前因工具缺失失败，修复后所选工具可发现、调用，未选工具保持不可见。

独立初始化还会把 Harness 声明、导出种子未列出的外部直连 MCP 保存到当前连接配置，保留 Header、工具选择与连接名；已有当前连接优先，本地分组不回连原平台。定向用例覆盖默认值、停用连接、当前配置优先及修改后重启保留。`report-write` 原配置因此不再丢失，但其外部服务当前拒绝连接，两个报告持久化工具不能记为已装载；不擅自修改外部服务。

宿主机 `assets/workspace/`、`assets/presets/`、`assets/managed/` 只读映射给容器，`state/home/` 单独持久化。编辑 Harness 后按实际装载机制重启，不构建派生镜像。LFX 的锁定 Python 与业务依赖随包通过目录映射使用，不改变标准镜像。

端口和访问地址由 `state/deployment.env` 的 `AGENT_PORT`、`AGENT_HOST` 维护，MCP 由 `state/home/standalone/config.json` 的 `mcp.servers` 维护。`./agent restart` 重建容器以更新端口映射并重新装载当前配置；初始种子不覆盖已有配置。CLI 的 `start`、`restart`、`configure` 接受指定连接 ID、地址和 Token；`configure` 只保存，`start` 带连接参数时重新装载，SDK 任务不自动重放。`-h` 及无效参数均显示帮助。

配置地址变化会改变 OpenAPI 资源 URI。共用 MCP 管理器复用已有的唯一同路径匹配，在所属连接的当前目录中解析已选资源与模板；歧义和未选资源不装载，读取同样核对当前选择。没有额外保存另一份地址事实。

## 验收服务残留补查

用户指出 28027、28028 仍可访问后，实际查询两个实例的原生会话，确认无在途任务，再通过 `platform/dsh-deploy agent-cleanup` 清理。此前把保留 Run 证据误当成保留运行服务的理由，导致清理范围遗漏。两个实例的 HOME、会话、Run 和报告均保留，页面现已关闭。

继续按安装目录、Compose 标签及挂载清点，还发现缺少 `deployment.env` 的旧 EXP027 导出探针，以及两个更早验收目录中的三个 Compose 项目。维护工具现按实际归属发现同目录历史项目，可处理旧探针；发现混入其他安装的容器时拒绝删除。清理后重新检查容器与网络，残留时报告失败并保留介质。六项定向回归通过，覆盖失败保留、无身份探针、多项目、外来容器及容器和网络残留。

[补查回执](acceptance-cleanup.json)记录五个安装目录、六个项目共 12 个容器及对应网络已清理；28027、28028 的 TCP 连接失败、HTTP 页面不可达，目标容器和网络均无残留。五个 HOME 共 97 个普通运行文件逐项摘要比对无变化；另删除一个无状态旧安装解压源。当前工作区已无其他旧独立验收容器或遗留 Compose 网络。

当前仅保留 28033 的本次修订包验收入口，等待用户页面验收，验收结束后清理。28032、18501 属于其他用户安装，正式业务实例及共享标准镜像继续保留。通用收尾要求由[验收环境收尾](../../../../../docs/platform-design/23_离线一键打包与安装.md#验收环境收尾)维护，研发技能引用该合同，不以保留证据为由继续开放已结束用途的服务。
