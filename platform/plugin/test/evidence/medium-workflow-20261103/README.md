# 算力变体固定流程与并发评测核验

本次覆盖 `PA-04/08/10/12`，来源为 EXP024 与 `VAR-security-operations-expert-003-r6fcbc8e8f093`。真实训练耗时 24.38 秒，材料见[训练记录](../medium-training-20261102/README.md)；本次集中减少训练之外的重复构建、逐次工具往返和串行等待。

`compute-variants/prepare` 连续核对并完成受控构建与本地冻结，返回固定提交；有效构建按源码、Candidate、runner 和依赖摘要复用。失败回执保留当前阶段和已完成步骤。`eval/batch-start` 对 1–8 个固定来源请求整批预检，再启动独立 Run；相同请求 ID 与参数恢复时不重放，新参数必须使用新 ID。原生训练命令卡已有命令摘要、进程身份、状态和双端工件摘要，本次复用该能力，没有另建训练调度器。

API 执行器接受 1–8 的并发上限，只有显式列入 `parallel_cases` 的独立用例并行，其他用例构成 Run 内独占屏障。各 Case 仍有独立 Session 和原始证据，结果按原顺序封存；安全停止后等待已发出的任务收尾，不再启动后续用例。跨 Run 的共享写入仍须隔离或分批执行。用例、并发和独立用例列表均进入 Run 输入锁。

独立场景复核沿用 Run 中冻结的并发上限，每个场景使用独立 Session，结果按输入顺序保存。机器回执先解析再脱敏，保留数字、布尔值和 Run 关联；短凭据只替换完整字符串。模型配置保存、读取与实例启动共用内核文件锁，锁文件可以保留，进程退出后自动释放占用。

评审输入显式提供证据索引与逐条要求的输出结构，严格证据校验保持不变。子进程失败回执保留已脱敏的错误说明；旧 Run 缺少该说明时，根因仍记未知。

评测预览、启动和批量启动接受 `program_root`，从已构建的隔离程序目录执行，仍由平台投影模型策略并注入凭据。路径作为程序来源保留，凭据只进入子进程环境；不改变平台自身的程序根。
