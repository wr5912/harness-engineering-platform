# 平台页面共同错误整改

本次核对本机 18120 的首页、管理对话、智能体管理、评测中心、实例管理、统一网关及 MCP 管理，覆盖列表、关键只读详情、筛选、刷新和窄屏。未执行新的业务评测、业务写入或远端部署。

## 根因与修正

| 根因 | 直接影响 | 修正 |
| --- | --- | --- |
| 实例状态包含每个实例完整的依赖文件清单，三实例响应约 1.78 MB，超过后端命令的 1 MiB 读取上限 | 实例列表失败，并影响首页与其他实例状态消费者；错误中夹带大量 JSON | 状态只返回加载回执摘要和变化项，完整清单继续保存在原登记中参与差异核对；命令读取上限兼容已有大回执，失败使用明确错误信息 |
| 历史中断 Run 已有恢复说明，但 TypeScript 读取器仍直接解析空的冻结输入和执行文件；旧请求回溯跨版本扫描 | 单条历史故障扩散为多条评测列表错误，并阻塞首页 | 对齐已有恢复合同，按所属版本和原文件摘要核对恢复关联；缺失冻结证据保持未知；保留历史失败与原文件；已删除版本的终态旧请求不冒充当前 Run 故障 |
| 平台登录 Cookie 名称与原生插件的浏览器身份入口不同 | 管理对话任务面板返回 `TASK_BROWSER_AUTH_REQUIRED` | 平台使用 DSH 原生的按 Host 命名 Cookie，继续通过平台会话记录验证；旧登录在页面读取时迁移，退出同时撤销旧新入口 |
| 更新前核对把已结束的历史证据读取故障等同在途任务，且进程切换后可能复用旧 HTTP 连接 | 修复读取器的更新被自身阻塞，更新后核对可能误报连接失败 | 仅对身份、工作区、终态与进程退出均已核对的旧请求区分处理；子会话使用真实运行状态；进程切换核对关闭连接复用，并给原生会话清单保留读取时间 |
| 实例状态查询写入派生文件 `asset-file-cache.json`，文件监听将该缓存当作资产变更，再触发查询 | 每秒刷新实例、智能体目录与首页，较慢的网关响应不断被新请求取代，页面持续加载 | 在共同监听入口排除该派生缓存；真实实例登记、资产与运行状态变更仍通知直接消费者 |

## 验证

- 实例资产测试 12/12、实例管理测试 33/33、实例重载测试 11/11、评测任务测试 40/40、页面相关测试 337/337、登录测试 15/15、更新工具测试 22/22、文件通知测试 7/7 通过；类型检查与隔离构建通过。这些是受影响路径检查，未执行全仓测试。
- 实例正常状态及来源无法核对的降级状态均只返回回执摘要，持久化逐文件清单保持完整。真实文件监听检查覆盖三次原子替换状态缓存不通知、修改实例登记仍通知实例及智能体目录。
- 首次修复生效后，实际接口返回 4 个实例、38 份 Run，评测列表 `pending=0`、`errors=0`。历史恢复 Run 保持 failed、冻结输入不可用、用例为空，不补写历史证据。
- 第一轮实际 Chrome 七入口核对只剩管理对话的任务认证 403；该错误单独定位和修正，不能将这一轮写为全部无错误。
- 四个实例的概览、运行日志、刷新和筛选，以及正常 Run 和恢复 Run 的概览、逐例结果、产物文件、决策样本与刷新完成核对。恢复 Run 的中断提示属于真实历史状态。
- 智能体概览、描述与技能、Harness 资产、算力变体，以及 390 px 首页、实例管理、评测中心完成实际页面核对，无浏览器、接口或页面错误，文档横向宽度保持 390 px。
- 最终受管重启后，真实 Chrome 完成七个入口共 18 个检查点，包含实例与评测手动刷新、网关四个页签、首页整页刷新及三页 390 px 窄屏。各页数据已加载，可见错误提示为 0，console 错误及警告、页面异常、HTTP/RPC 错误和非导航网络失败均为 0；三页窄屏文档横向宽度均为 390 px。首页加载后静置 15 秒仅有 6 次正常助手状态轮询，没有实例或智能体列表重读。最终回执为开发工作区 `.local/home-errors-20261104/readiness-final.json`。
- 原生任务浏览器入口使用本次平台登录返回 200，旧登录迁移后仍返回 200；退出后同一入口返回 401。认证探针只读取任务；最终更新另按用户允许重启的授权停止在途管理任务。
- 稳定加载探针曾因错误定位管理对话的 `main` 元素超时，已改为核对实际原生对话槽；页面导航期间的 `ERR_ABORTED` 单独记录，其他网络、console 及接口错误仍导致检查失败。后续一轮出现一次 CSS 请求 `ERR_NETWORK_CHANGED` 及对应 console 错误，失败记录保留；该资源连续三次复读均为 200、`text/css`、77,471 字节。
- 首轮已生效更新后，445 个原有管理会话无缺失，9 个当时保留的业务容器身份、启动时间、状态及端口保持一致。最终重启前后再次核对，456 个管理会话全部保留，运行任务为 0；4 个登记业务实例仍在运行，全主机 40 个既有容器的身份、启动时间、状态及端口均未变化。本次平台更新未重启业务实例。

五项修复均已通过 `platform/dsh-deploy update` 在本机生效。最终更新初次因在途子会话返回 `busy`；按用户允许重启的授权，通过既有取消及子会话中断入口停止任务后重试，工具返回 `applied`、`activation=managed-restart`、`busy=[]`。平台 PID 从 839069 切换至 1067167，原 HOME、工作区和公开入口保留；维护回执为 `.local/platform-updates/80ead442-a8fa-4c52-83cb-1882a0596d55/receipt.json`。重启后的原生任务浏览器入口再次返回 200。中途失败的更新回执与原始探针保留在当前开发工作区 `.local/home-errors-20261104/`；其中包含业务原文，不作为可提交证据。
