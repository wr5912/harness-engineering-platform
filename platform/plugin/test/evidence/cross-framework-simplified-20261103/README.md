# 跨框架登记与访问简化验收

本次专项覆盖登记、访问两个弹窗，连接、改名及入口授权的直接编辑路径，以及它们调用的发现、登记、会话与适配代码。未作全项目后端审查。当前接口以[服务合同](../../../../../docs/platform-design/04_核心业务闭环与服务接口.md#cross-framework-access)维护，使用方法见[接入说明](../../../../../docs/platform-design/27_跨框架接入使用说明.md)。此前正式接入的[原始验收](../cross-framework-formal-20261103/README.md)保留为历史证据。

## 审查与实现

已确认的复杂度来自前端按协议参数组织任务：登记收集内部目标标识和可默认信息，普通访问要求手动创建、发送、读取，原生响应与本轮执行完成混在一起。当前改为原生名称发现、服务端默认值，以及一次发送和只读结果查询；前端移除无控件字段及重复默认配置，编辑只提交当前任务的字段。

认证、目标绑定、会话归属、原生消息锚点和幂等回执均有实际消费者，不能据界面复杂直接判为冗余。会话编排复用已有请求与映射，不新建任务账本、调度器、数据库或配置平台；运行状态由原框架即时读取。独立审查核对了受限DSH发现、旧AgentScope连接身份、局部保存、未派发拒绝、未知结果恢复、刷新与跨对象草稿，发现项已修正。

## 限制

模型及业务资源仍采用确定性模拟边界，框架Runtime是真实源码服务；本轮不证明真实业务质量、异地主机、完整原生Web/WS、取消或生产部署。

[OpenCode只读定位](runtime/opencode-initialization-readonly.json)确认失败请求的用户输入完整且原生没有工具事件。锁定版MCP连接与工具注册异步进行，公开接口没有可靠的工具注册就绪等待合同。冷态与初始化后观察、原生源码支持初始化时机有关的推断；未采集该次原始模型工具列表，不能将推断写成已捕获的模型事实。本次不修改外部源码，不加入固定睡眠、强制重连或等待全部MCP成功的发送门禁；后续公开就绪合同可用时再复用。

凭据精确扫描结果见[扫描回执](credential-scan.json)。不归档凭据、Cookie、token、原生HOME或私钥；截图不做OCR，扫描不构成全仓无凭据声明。
