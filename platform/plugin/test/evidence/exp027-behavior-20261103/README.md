## 根因及变更

业务 Persona 将 DSH 容器运行方式写为角色身份；本地巡检要求同轮启动，而外部服务实际强制下一轮确认。短请求还会被模型补成 `ALL`，没有沿用服务已公开的任务默认范围。原启动状态只有已尝试和成功回执，错误后会留下未知提交，不能承诺用户再确认即可启动。

实际浏览器验证进一步发现：锁定 RC5 的 `systemPrompt.assemble()` 早于 `agent/pre-step`，只在后者适配工具会遗漏首轮。修改目标插件，通过公开 `agent/created` 提前安装主 Agent 的适配，保留原会话补充路径；没有修改 DSH 源码或增加输出过滤器。

数据侧修改主 Persona、Preset 简介、工作区角色、巡检 Skill、运行插件 TypeScript、受控生成的 ESM 及 `change.yaml`。任务默认范围省略 `deviceSelector`，显式范围继续沿用原输入；保存错误回执及原请求身份，未知时不重复提交、不虚构查账工具、不要求用户再次确认。
