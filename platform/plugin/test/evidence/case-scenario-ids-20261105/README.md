## 工具调研与采纳

| 已有能力或方案 | 本次判断 |
| --- | --- |
| [Git merge-file](https://git-scm.com/docs/git-merge-file) | 采用现有 `-p --diff3`，无冲突文本机械合并，模型只处理需要业务判断的差异与冲突。兼容当前 Git 2.34.1，离线依赖不增加 |
| [Git merge-tree](https://git-scm.com/docs/git-merge-tree) | 新版 `--write-tree` 适合提交树合并；当前包含未提交 Candidate 资产的流程及旧 Git 兼容要求下，保留现有实现 |
| [Git rerere](https://git-scm.com/docs/git-rerere) | 复用冲突解决的思路有价值，但依赖 Git 冲突与索引流程；当前通过已有 operation 草稿和有效验证续办，不增加第二份冲突缓存或全局配置 |
| [Git range-diff](https://git-scm.com/docs/git-range-diff) | 适合人工比较提交序列，输出不作为稳定机器合同；不替换当前资产差异与摘要校验 |
| [Beyond Compare Linux 安装包](https://www.scootersoftware.com/kb/linux_install) | 官方未提供原生 Linux ARM64 包；保持人工可选辅助，不加入双架构离线必需依赖 |
