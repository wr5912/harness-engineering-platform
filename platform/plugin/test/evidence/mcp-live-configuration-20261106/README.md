本轮针对管理会话 `session-6a79ab7e-f558-4cc5-b45d-7cc2e4c52975` 中的巡检启动失败，核对平台执行合同及实际加载。业务目标为 `inspection-027-schedule-acceptance`，来源为 `EXP-security-operations-expert-027-f-r3ba4799b0cb7`。

## 原因与修改

历史失败发生在平台实现摘要校验阶段，尚未取得巡检运行 ID、调用外部业务接口或生成报告。发布时保存的总摘要包含平台实现与连接配置；此前普通调用也要求当前总摘要与发布时完全相同，导致平台或连接更新后已有发布组合被拒绝。现有历史材料不足以确定当时具体改了哪个连接或哪段代码，不能归因为外部 MCP 服务故障。

普通调用改为使用当前实现及连接配置，保留冻结流程、模块和固定子版本的完整性校验。显式提供实现摘要的固定研究与评测仍严格核对。新运行记录当前实际摘要；请求去重沿用发布身份，配置变化不重放已受理操作。

“常规巡检未指定范围默认全部资产”是用户已确认的设定。管理助手已撤回将 `scope.all=true` 判为错误及增加范围门禁的建议。

管理侧 `mcp-composition` 技能已区分配置保存的 revision 冲突与执行摘要冲突，要求排障先核对实例来源的当前业务设定；不再以平台或连接更新为理由建议重新发布，也不擅自替换固定研究来源。该技能通过 DSH 原生读取装载，不改写原生对话或执行循环。
