# 18120 平台稳定性核验

核验日期：2026-11-10

本记录只保留当前实现、运行回执和验证边界。目标是避免一次发现任务、模型重试或平台退出将管理助手和其他业务路径一并拖垮。

## 当前实现

- MCP 与 OpenAPI 发现共用有界预算：递归深度、节点数、序列化字节数、目录条目数和流式响应大小均受限；共享 `$ref` 按实际展开计数。
- 发现请求使用全局并发上限、有限队列、同一服务指纹去重和按等待者取消；最后一个等待者取消时释放上游请求。
- OpenAPI 读取、登录、401 重试和响应体释放共用取消链；部分发现结果保留各自真实原因。
- `llm-openai-codex` 只启用明确的十次重试策略和有限可重试错误码，未扩大到业务错误；配置由平台更新工具写入数据根并可回滚。
- 模型投影只校验当前选中的模型，其他模型的坏配置不阻断健康模型；会话历史冷迁移只处理属于当前工作区的旧记录，使用原生 Session 恢复接口，不激活 Agent。
- 心跳写入在校验和幂等边界内执行；平台生命周期区分显式停止、启动失败和异常退出，systemd 保持前台进程、有限重启间隔和数据目录。
- 默认 Node.js 堆上限为 8 GiB；状态接口同时显示配置值与运行进程实际值。
