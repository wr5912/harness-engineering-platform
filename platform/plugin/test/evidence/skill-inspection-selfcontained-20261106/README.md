## 独立状态组合撤除

选定交付源码删除 inspection-status 的目录、登记、公开选择与 Candidate 调用入口；状态事实由 Skill 直接调用原始只读工具，完整常规巡检在包内处理同次状态证据，不额外发起 SOC 请求。剩余基线、漏洞、可达性、常规及深度五项，各自的业务取舍见数据侧组合资产包；不以五这个数量作为优化目标或性能结论。

实际删除试验发现：旧平台把未被当前入口引用的历史版本也作为删除阻碍，并在列表中计算其完整依赖，导致子组合删除后整个列表失败。程序改为从当前草稿和发布入口追踪固定版本的传递依赖；历史依赖缺失只使该历史版本没有执行绑定，仍保留身份、配置及原因。当前版本的校验和固定调用保持严格。历史 Run 与已发布父版本不改写。

选定五项源码的原生图回归 16 项、程序 MCP 回归 43 项、Candidate 来源与 Guard 回归 16 项通过，TypeScript 检查通过。程序回归覆盖历史列表、当前传递依赖及失效旧版本拒绝执行；隔离加载新处理器与选定数据后，真实 list 处理器返回五项巡检，当前执行绑定有效，六个历史版本因缺失依赖保留为不可执行。日志见 [撤除验证](logs/retire-status/)。Candidate 全量测试的五项 department-catalog 数量失败在修改前同样存在，不混作本次回归，也未扩大修改策略迁移。
