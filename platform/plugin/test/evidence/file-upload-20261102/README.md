# 实例文件上传修复与实际验证

涉及 `PA-05/08/12`。基线、实际核对时间、实例及摘要见 [verification.json](verification.json)，对应基线后的工作树修改。

共同根因在业务 Runtime 的原生 API 桥：所有 POST 都经过 JSON 解析和 1 MiB 限制，并以 UTF-8 重建正文，破坏了 DSH RC5 的流式二进制上传合同。已发布身份另受原生精确上传路由的 owner 限制影响。

桥接层现按原生 `requestBodyMode` 转发流，保留二进制、背压和取消信号。上传前从查询参数核对 Session 归属与可读权限；仅对已经通过该核对的原生上传请求使用临时 owner Peer。普通 JSON RPC、其他路由和会话归属合同保持原有处理。

[接入回归](business-gateway-tests.log) 46 项通过，覆盖共享开发与已发布认证模式的大文件、中文名称、原生回执解析、跨主体和未知会话拒绝，以及原生 400/415 错误。文件存储在集成测试中使用边界夹具，实际运行验证直接使用 DSH 原生附件存储。包含并行算力开发改动的当前工作树完整插件回归为 1506/1506，无失败或跳过。另将仅含本次暂存修复的源码导出到隔离目录，构建及 46 项接入回归通过，排除对未提交并行改动的依赖。

当前开发环境的 7 个运行实例逐一重载，容器、镜像、卷和端口保持一致；管理平台进程未重启。每个实例上传 2,097,165 字节随机文件，核对回执、实际落盘字节和 SHA-256，原有共 113 个会话全部仍可列出。实际 Chrome 在用户指出的实例选择合成 XLSX，上传返回 200，附件卡片显示文件名与大小，页面无运行异常，见[截图](upload-ui.png)。未操作原用户会话，未发送业务指令。

当前实机实例均为匿名开发模式；已发布认证模式由原生路由集成测试核对。本记录不证明表格业务解析或策略执行，未同步远端部署环境。
